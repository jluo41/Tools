🔗  Wiring — how _WorkSpace reaches the In-Lab UI
═══════════════════════════════════════════════════════════════════

The pipeline cooks parquet stores into _WorkSpace. Since 261009 the console
READS them in place: a record set is read per request and assembled into the
per-human json the engine speaks (record_store.py, beside the engine's json
reader), and a case set is read as cooked (case_store.py). The per-human json
COPY is the fallback, used only where no record store is mounted.

─§ The two ways across, and which one is used ────────────────────

  🗄️ _WorkSpace (parquet, pipeline-native)          🖥️ Console (json, UI-native)
  +----------------------------+                    +----------------------+
  | 2-RecStore/<RecSet>/       |  ── ② read in ────▶| per-human json,      |
  |   Record-*/RecAttr.parquet |     place, per     |   assembled per      |
  |                            |     request        |   request, cached    |
  | 3-CaseStore/<RecSet>/      |  ── read as ──────▶| 📌 cases + facets     |
  |   @v<k>CaseSet-*/          |     cooked         |                      |
  +----------------------------+                    +----------------------+
               │
               └─ ① copy (the fallback) ─▶ 📦 InLabStore/<dataset>/patients/*.json

  ✅ ② READ IN PLACE (chosen 261009, j02 Q02): INLAB_RECORD_STORE; each record
     set is a dataset; one source of truth, always fresh, no second copy of
     patient data to secure. Cost: a parquet filter per request, cached per
     human. A record store has no raw layer: the Raw view says so.
  ↩︎ ① COPY (fallback): INLAB_DATASET_STORE / INLAB_PATIENT_STORE; used where
     no record store is mounted. A record set wins over a copy of the same name.

─§ Every console mount ← its _WorkSpace source ───────────────────

  +------------------+---------------------------+-------------+-------------+
  | 🖥️ Console needs  | 🗄️ _WorkSpace source       | 🔀 via       | 🌐 router    |
  +------------------+---------------------------+-------------+-------------+
  | 👥 patients/record| 2-RecStore/<RecSet>        | read in place| console_api |
  | 📌 cases          | 3-CaseStore/<RecSet>/@v*   | as cooked   | labeling_api|
  | 🧠 endpoints      | 6-EndpointStore            | as-is       | console_api |
  | ✏️ labels         | <project>/tasks (label dims)| as-is       | labeling_api|
  | 📋 task feed      | examples-*/Project-*/tasks | as-is       | tasks_api   |
  +------------------+---------------------------+-------------+-------------+

  read in place (parquet)  : patients · cases
  used as-is (dir mount)   : endpoints · labels · projects
  copied (the fallback)    : patients, as InLabStore/<dataset>/patients/*.json

─§ The env vars that mount each one ──────────────────────────────

  🔧 INLAB_RECORD_STORE   = _WorkSpace/2-RecStore          (each record set is a dataset)
  🔧 INLAB_CASE_STORE     = _WorkSpace/3-CaseStore         (<RecSet>/@v<k>CaseSet-*/)
  🔧 INLAB_DATASET_STORE  = _WorkSpace/InLabStore          (the copy: <dataset>/patients)
  🔧 INLAB_PATIENT_STORE  = …/InLabStore/<dataset>/patients (single, back-compat)
  🔧 INLAB_ENDPOINT_STORE = _WorkSpace/6-EndpointStore
  🔧 INLAB_REGISTRY       = …/endpoints.json            {package: url}
  🔧 INLAB_LABEL_STORES   = {"<dataset>": "<project>/tasks"}
  🔧 INLAB_PROJECTS_ROOT  = the SPACE root               (examples-*/Project-*/tasks)
  🔧 INLAB_RECORD_TABLE_NAMES = {"<RecordName>": "<table>"}  (optional renames)

─§ Reading a record set in place (record_store.py) ───────────────

  🗄️ 2-RecStore/<RecSet>/[@i<k>n<n>/]
       manifest.json  structure.humans · structure.records
       Human-<H>/Human2RawNum.parquet          → who is in it (the id column)
       Record-<H>.<R>/RecAttr.parquet          → one human's rows, filtered by id
                    │  ⚙️ per request, cached: every Record's rows for that id
                    ▼
     {
       patient_id, summary{cohort, table_counts, anchor, sex · birth date if a
                           one-row Record carries them},
       provenance: [the endpoints whose required tables this human carries],
       source_tables: { <R without its time grain>: […] },
       layers: { record: { tables: { Rec.<R>: … } } }
     }

  No table or column is named: the id column is the one every Record shares,
  the time columns are the timestamp and date columns, by type.

─§ Reading a case set (case_store.py) ────────────────────────────

  🗄️ 3-CaseStore/<RecSet>/@v<k>CaseSet-<Trigger>/
       df_case.parquet      one row per case (id, ObsDT, trigger columns)
       @<CaseFn>.parquet    that CaseFn's facets, row for row with df_case
  → 📌 one case per trigger moment, its facets summarised by shape.
     No case set: a record row that holds prose (5+ words) is a case; a
     timeline of numbers has none until it is cooked.

─§ End-to-end trace (any dataset) ────────────────────────────────

  cook           2-RecStore/<RecSet>               (RecordFn output)
   ▼ mount       INLAB_RECORD_STORE=_WorkSpace/2-RecStore
   ▼ scope       GET /api/patients?dataset=<RecSet> → ep.RECORD_SET set
   ▼ render      👥 roster · 🧾 record: one lane per table with a time column
   ▼ cut         📌 case = a trigger moment of 3-CaseStore/<RecSet>/@v*CaseSet-*
   ▼ attach      ✏️ label (if a label store maps this dataset) / 🧠 score (if endpoint)

─§ Adding a new dataset (the checklist) ──────────────────────────

  1. 🍳 cook the RecSet    → 2-RecStore/<Name>          (/haipipe-data record)
  2. 🔧 it auto-appears    → INLAB_RECORD_STORE lists every record set
  3. 📌 (optional) cook a case set → 3-CaseStore/<Name>/@v0CaseSet-<Trigger>
  4. ✏️ (optional) map a label store in INLAB_LABEL_STORES[<dataset>]
  5. 🧠 (optional) package an endpoint → 6-EndpointStore + registry entry
