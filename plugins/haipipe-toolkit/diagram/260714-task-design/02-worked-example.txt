ONE CONCRETE CASE
=================

  Input: `/haipipe-task plan examples/ProjA/tasks/A01_pretraining/01_train_clm`

  This is the INSTANCE consuming the PATTERN. Trace every file it touches.


① plan verb → stage-plan.md
===========================

```text
   fn/stage-plan.md:8    reads →  haipipe-workflow/ref/plan-schema.md   (SCHEMA SoT)
   fn/stage-plan.md:9    reads →  haipipe-workflow/ref/concepts.md
   fn/stage-plan.md:58   Step 1 →  RUN fn/audit.md on the folder
```

  So the FIRST thing the `plan` instance does is call the task-only AUDIT —
  a step that has NO counterpart in the generic haipipe-workflow lifecycle.


② audit runs (read-only, four sisters)
======================================

```text
   fn/audit.md  scans  configs/  runs/  results/  notebooks/
     run_1m:   configs ✅  runs ✅  results ✅  notebooks ✅
   returns:  type=fit, run_names=[run_1m], issues=[], workflow_exists=false
```

  Nothing on disk changes. Audit is `inspect` in spirit, but the fn never says so.


③ stage-plan writes the TWO layers
==================================

```text
   📄 workflow/plan.yaml                 phases = Run · Gate1 · Gate2
                                         (task-specific — NOT in the generic schema
                                          example, which uses Load/Author/Validate/Review)
   📄 workflow/plan-script-01_train_clm.yaml   phases = the script's internal # %% cells
```

  Both obey plan-schema.md's step fields (label/type/required/prompt/files_in/
  files_out). The Gate1/Gate2 phases pin agentType: haipipe-task-reviewer-agent.


④ execute — and here the generic lifecycle is BYPASSED
======================================================

```text
   generic haipipe-workflow says:  plan.yaml ──build──▶ .workflow.js ──execute──▶ results
   what task ACTUALLY does:        ref/task-lifecycle.workflow.js is HAND-SHIPPED;
                                   runs/run_1m.sh executes the .py via papermill.
   ⇒ `build` never fires. plan.yaml is an OBSERVABILITY record, not a compile input.
```


⑤ stage-report mirrors the plan
===============================

```text
   fn/stage-report.md  reads plan*.yaml + results/run_1m/ → writes
   📄 workflow/report.yaml               same Run/Gate1/Gate2 phases, filled
   📄 workflow/report-script-01_train_clm.yaml
```

      but the run.sh + schemas write metrics.json + runtime.yaml. The reporter
      scans the WRONG files. See 06 · H1.
