2 — THE FOUR PHASES
====================

  The positive half of the ruling. If the front door is not a set of
  escape hatches into the bank, what IS it? Stages. Each stage runs
  four phases. PROBE is the only one that touches the bank.


The front door exposes STAGES, not executors.
----------------------------------------------

```text
   /haipipe-paper                      /haipipe-application
   ─────────────                       ────────────────────
   seed · resource · claims            seed · claims
   pitch · narrative · display         venue · pitch · narrative
   section-edit · round · rebuttal     display · section-edit · round

   (+ enter/status/venue — console & routing, no bank contact)
```

A user advances a STAGE. That is the whole vocabulary.
There is no `discover`, no `task`. Those were never stages;
they were holes cut in the wall.


Every stage runs the same four phases (DPRC).
---------------------------------------------

```text
   ┌──────────────────────────────────────────────────────────┐
   │  A STAGE  (e.g. claims, display, section-edit)             │
   │                                                            │
   │   DRAFT ───▶ PROBE ───▶ REVISE ───▶ CHECK                  │
   │   write &    collect    weave in    human gate             │
   │   raise      evidence    evidence                          │
   │   gaps         │                                           │
   │                │  the ONLY phase that touches the bank      │
   └────────────────┼───────────────────────────────────────────┘
                    ▼
             1-probes/PPNN_<topic>.md      (probe files, one per topic)
                    │
                    ▼  clean-context agent — the commission, verbatim
             Agent(haipipe-task-orchestrator-agent)
             Agent(haipipe-discovery-orchestrator-agent)
                    │  their blindness IS the wall (LAW 2)
                    ▼
             <task-folder>/QA/<n>-<slug>.md    the answer, in GENERAL words
```

DRAFT raises the questions. (260714-probe-qa: "DRAFT is where the
questions are born.")
PROBE collects them into probe files and commissions the ones that
cannot be answered from the bank as it already stands.
REVISE weaves the returned reading in.
CHECK is the human gate.

Nowhere in that loop does the consumer session run bank work itself.
The only crossing is a STRING in a clean agent's prompt.


So the picture, whole
---------------------

```text
   BEFORE                              AFTER
   ──────                              ─────
   front door ┬ stage verbs           front door ┬ stage verbs ─┐
              ├ probe   ─▶ bank ✅               └ probe ───────┤ one door
              ├ discover ─▶ bank ❌                              │
              └ task     ─▶ bank ❌               each stage's PROBE phase
                                                  is the ONLY bank contact,
              three roads to the bank             and it goes through a
              (two of them jump the wall)         probe file + clean agent

                                                  one road to the bank.
```

The phase-verb pass-through already in the skill —

    /haipipe-paper edit 4-llmtrait revise   → the stage drives its REVISE phase

— is exactly the mechanism JL is pointing at. It stays. We are just
removing the two verbs that let a user skip the stages entirely and
land in the bank.


One consequence to keep honest
------------------------------

"Non-claim utility work" (a quick lit scan, a data sanity check) does
not get a special lane anymore. Two honest routes remain:

    1. it is evidence for a stage  → it is a PROBE question. Raise it.
    2. it is genuinely standalone  → a HUMAN uses the bank's own door
                                      /haipipe-task qa · /haipipe-discovery qa
                                      (not the paper. See file 01.)

If neither fits, the need was probably a claim in disguise.
