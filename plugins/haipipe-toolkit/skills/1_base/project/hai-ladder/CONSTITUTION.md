# Ladder · Constitution

## A01 · Containment and work kind compose

> “它有两个维度，一个就是这个 layer 的这个维度”
> “同时呢，我们这个 workflow 它有不同的种类。”

Source: the user's design request, 2026-11-27; implementation approved with
“OK好，那你开始去执行吧。” after the file plan.

**Rule:** Ladder chooses placement across Project, Block, Job, Task, Run and
Studio. The work-kind entry supplies the method and acceptance rules. Theme is
a grouping, not a mandatory execution record. Each level retains its own writer;
the combination does not require another skill for every intersection.

**Check:** Given a source-review request, choose Discovery with the relevant
record owner; given a repeated execution, consult the existing Task and Run
contract before proposing another Block. Explain the scope decision.

## A02 · Hierarchy is not a required process sequence

**Rule:** Create only records needed by the work and allowed by its owner. Learning
can remain in Studio without a practice Job. Dependencies and execution gates stay
with hai-run's Workflow contract; Project keeps its existing shape audits.
Ladder supplies routing, not a second schema table or executor.

**Check:** A concept-only learning request produces no artificial Run; a request
for branching execution routes to the Run owner without changing the containment
hierarchy. Cross-Block reuse identifies the producer's output rather than copying it.

**Validation:** Fresh-context skill exercises following the root README; record
the exercised cases and results in the owning Blueprint Trace.
