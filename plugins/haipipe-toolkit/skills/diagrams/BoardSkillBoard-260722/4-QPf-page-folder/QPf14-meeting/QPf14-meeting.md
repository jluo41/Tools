# Meeting · a page's own kept record of a conversation
state: 🟡 PARTIAL · shipped and proven on its own specimen 260818 · open: the 🗣 tab itself
owner: JL
method: let a page keep a person's own record of a conversation that bears on its argument, one dated folder per meeting, read newest first, standing apart from the separate Meeting-<n> page type

## Opening
When a conversation changes what a page argues, where does the record of that conversation live?
The roster named this plugin on 260815 and left it 📋 declared: a folder shape with no skill and no writer, three days before this page existed.
This page settles the one question that was actually open: does a kept meeting point at the separate `Meeting-<n>` page type, or stand on its own. It ships the writer the row had been waiting on.

**Its cousin, and why it is not this plugin**: `Meeting-<n>` (`haipipe-page-for-meeting`, generated by `cli/meetingpage.py`) is a whole board page recording a conversation that OWES a decision to some other page; its own closing rule says a decision spoken there is not ruled until it lands on the page that owns the subject. This plugin owes nothing to route. A meeting kept here is material for the page it sits beside, the same way `draw/` holds a scene and `chat/` holds a session: attached, not routed.

**Covered elsewhere**: the list of plugin names is `../../haipipe-plugin/ref/roster.md`. `../../page-types/haipipe-page-for-meeting/SKILL.md` is the separate page type this plugin deliberately does not point at.

## Diagram
**No store, no rank**: unlike task or pagex, a meeting is read by when it happened, not by a person's chosen order.
```text
  🧑 a person, after a real conversation
        │  types what it decided, and optionally pastes the raw exchange
        ▼
  🗣 meeting/<YYMMDD-HHMM>/         PRIMARY · server-stamped, one per kept meeting
        digest.md      what it decided · required · the reading path
        transcript.md  the raw exchange · optional · reference only
        │
        ▼ the view lists every kept folder, newest first
  ⚙️ meeting/<stem>-view.html      DERIVED · the 🗣 card view, re-minted on open
```
The kept folders ARE the record; the view is a read-only projection of them, rebuilt on every open like every other plugin's derived half.

## Content
### 1 · What gets kept, and what the folder name means
**One folder per meeting, timestamped by the server**: the shape the roster named on 260815, unchanged.
```text
  🗃 PRIMARY   meeting/<YYMMDD-HHMM>/digest.md         required
  🗃 PRIMARY   meeting/<YYMMDD-HHMM>/transcript.md      optional
  ⚙️ DERIVED   meeting/<stem>-view.html                 re-minted, never hand-edited
  ⚖️ the rule  the stamp is the SERVER clock, so two people in different
                time zones land on the same board's own idea of "now"
```
📌 A meeting is kept by typing a digest into the tab's form; the folder and its timestamp are the server's to write, not the person's.

A folder name colliding with an existing stamp (two meetings kept in the same minute) gets a numeric suffix rather than overwriting, the same collision rule the board's own comment writers use elsewhere.

### 2 · Why standalone, and what that costs
**Two shapes were on the table**: point at `Meeting-<n>` pages, or keep the roster's own declared shape. JL chose standalone.
```text
  🅰 point at Meeting-<n>    reuses the real generator and its one contract;
                              costs: a meeting bearing on THIS page's argument
                              now lives on a page named for the meeting, not
                              for the argument, and every reader has to open
                              a second page to read three sentences
  🅱 standalone (shipped)    the record sits beside the page it explains;
                              costs: nothing routes it, so a decision a
                              meeting produces for ANOTHER page still needs
                              a person to notice and carry it there by hand
                              (the same gap Meeting-<n> pages have always had)
```
📌 A meeting kept here explains THIS page and nothing else; a decision it produces for some other page is still a person's job to carry over, exactly as it always was for `Meeting-<n>`.

### 3 · Read-only view, one writer
**The pen only ever adds**: no ✕, no ↩, unlike every ranked-list plugin on this board.
```text
  ✍️ meeting-entry   POST   {digest, transcript?, cast?} → one new folder
  👁 meeting          POST   list every kept folder, newest first, read-only
  ⛔ no remove        a kept meeting is a record, not a list a person curates
```
📌 Keeping a meeting is the only write this plugin has; nothing here edits or removes one afterward.

## Aims
### A1 · 🗣 What gets kept, and what the folder name means
- 🔨 A1.1 · A kept meeting always carries a digest; a transcript is optional.
  **Done when:** Submitting the form with an empty digest is refused, and with an empty transcript succeeds.
  **Now:** An empty digest was refused (`"a meeting needs at least a digest: what it decided"`) before any folder was written; a real digest with cast and transcript landed at `meeting/260818-2215/`, both proven directly over HTTP against the same two routes the tab's own form calls. The form itself, the `#mdigest`/`#mtranscript`/`#mcast` inputs and the `keepmeeting` click handler, was never driven from a browser; this machine has no Chrome extension attached.
- ✅ A1.2 · Two meetings kept in the same minute both land, neither overwritten.
  **Done when:** Keeping two meetings within the same server minute produces two folders.
  **Now:** A second submission in the same server minute landed at `260818-2215-2`, proving the collision suffix; it was a test artifact, not a real meeting, so it was removed by hand from disk afterward (this plugin's own writer has no delete route, by design, so the cleanup was not through it).


### A2 · ⚖️ Why standalone, and what that costs
- ✅ A2.1 · This plugin's cards never link to a `Meeting-<n>` page, and its SKILL.md states why.
  **Done when:** A cold read of the skill and the view shows no such link and states the routing boundary in one place.
  **Now:** Neither `live/meeting.py` nor `87-plugin-meeting.js` names a `Meeting-<n>` path anywhere, and this page's own §2 states the boundary in one place.


### A3 · 👁 Read-only view, one writer
- ✅ A3.1 · The view lists kept meetings newest first and writes nothing but itself.
  **Done when:** Opening the tab after keeping three meetings shows all three in reverse chronological order, and the store folder gains no other file.
  **Now:** `_meeting_render` sorted the kept folder correctly and the rendered card showed the digest text, the `cast:` line, and a `transcript.md` link, all read straight off the files on disk.
