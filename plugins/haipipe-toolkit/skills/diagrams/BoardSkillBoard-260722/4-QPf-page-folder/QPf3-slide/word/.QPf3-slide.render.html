3 · The one home and the two doors

**Where a deck lives and how it opens**: derivation, not registration.

Both doors HEAD the derived path: a saved deck shows, a missing one yields the pointer page naming the author path.

The deck links at html-ppt's own assets by relative path, so the same file opens over the server and off disk, and a theme improvement reaches every deck without a rebuild.

4 · What the dead type had that the plugin does not

**The acceptance gate**: the one idea worth carrying out of the archive.

The QBt9 specimen's law was that a person accepts each rendered slide, and no machine may tick that row.

An AI deck makes editorial choices, so it CAN misrepresent its page, and the plugin path currently has no acceptance surface at all.

Whether a deck presented to others needs a person's yes first is not ruled, and the aim below holds the question rather than letting it vanish with the type.
