\section{One path per page, and no list to keep in step}
\textbf{One path per page}: if the file is there, the page has a deck.

\begin{verbatim}
   <page>/slide/<page>-deck.html
   worked out from the page's own path, the way Draw finds its owner
   no list, no registry: ask for the path and you know
\end{verbatim}
📌 This part settles where a deck lives, and how both doors find it with no list to keep. A folded page (\texttt{<name>/<name>.md}) owns the \texttt{slide/} folder. The deck's file name is the page name plus \texttt{-deck.html}. Both doors below work this path out from the page they are on, so no list is kept and no list can go stale. When the file is not there, both views say so and offer the button. Nothing builds a deck behind your back.


\section{Two ways in, and neither can show you an old deck}

                                    with  regenerate in its header

📌 This part settles that both doors read the same saved file, and that neither can show you an old one. Both doors send a HEAD request for that path, which is a small web question that asks only whether a file is there. They show the saved deck, or a pointer to the ✨ button when there is none. Every load skips the browser cache, so a freshly written deck appears on the next click. An old copy in the window can never outlive the file it came from.


\section{One click rewrites the deck, and always replaces it}
\textbf{What the button does}: the steps it runs, and the file it replaces.

\begin{verbatim}
   click --> POST /_board/autodeck {file, prompt?}
           --> live/autodeck.py runs `claude -p` on the page's .md
           -->  slide/<page>-deck.html replaced --> the view reloads
   a few minutes . the status word says so while it thinks
\end{verbatim}
📌 This part settles that a rebuild always replaces the whole deck, so a lasting fix belongs on the page. The ask box is optional. Leave it empty and the deck presents the page's argument, or type an ask and the talk leans the way you asked. The server writes the \texttt{<head>} and its asset links itself, from real paths on disk. So the model starts writing at \texttt{<body>}, and a new deck can never miss its own stylesheets. The server also checks the result before it saves anything. It wants a whole document, at least three slides, and the asset links in place. If any of that is missing the new deck is refused, and the old file stays. A rebuild always overwrites, so a lasting fix belongs on the PAGE, and the page is what every rebuild reads.
