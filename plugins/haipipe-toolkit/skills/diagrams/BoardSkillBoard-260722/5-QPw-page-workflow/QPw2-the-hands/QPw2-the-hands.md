## Opening
Who runs a page's DRAFT, PROBE, REVISE and CHECK when no person is in the loop, and what may each hand touch?
Three dispatched agents answer it, and the split between them is the whole design.
The producer writes and never judges, the judge reads and never repairs, and the controller routes and never edits prose.
One agent doing all three would approve its own work, which is the exact failure CHECK exists to catch.
This page owns that split and records what each hand has really run.

**Where this page sits**: `QPw1` owns the loop itself, the time axis these hands move along.
This page owns the hands, which is a different question: the loop says when CHECK happens, and this page says who may perform it and what they may not touch while doing so.
`QF1` owns the gate the reviewer serves.

**What this page carries**: the three units sit in this page's `skill/` plugin as plugged snapshots.
Each unit's own contract file is the authority on its procedure and ships from `board/agents/`; this page judges the design, not the procedure.

**Why the maturities differ**: the creator has driven a real six-page fan-out, the reviewer is proven with one pass never exercised, and the orchestrator has never run as itself.
Nothing on this page is contested, and everything on it is waiting on a run.

## Writing Style
How this page must be written. Read it before editing, and edit to it.

**A hand is named by what it may NEVER do**: the identity of each unit is its boundary, so every description here ends at the line it cannot cross.
Writing "the reviewer checks the page" says nothing; writing "the reviewer returns a verdict and holds no write tools" says the design.

**Proven and reasoned are different words, and the page must not blur them**: say "has run" only where a real run exists, with its date.
A contract that reads well and has never been dispatched is reasoned, and this page's whole value is keeping those two apart.

**The unit's own file is the authority on its procedure**: when this page and an agent's contract file disagree about a step, the file wins and this page is wrong.
So describe the design here and never restate the procedure, because a copy drifts.

**Language and sentences**: English only, in the source and in the render.
Write one sentence per line, so a paragraph is consecutive lines rather than one long line.
No em-dashes: use a colon, a semicolon, a comma, parentheses, or simply start a new sentence.

## Content
### 1 · Three hands, and the sentence each may never cross
**Three units, one rule each**: the line a unit may not cross is its identity.

```text
🤲 THE THREE HANDS

  ✍️ creator       writes ONE page in a fresh context
                   batch = N creators, one page each
                   🚫 a self-check is evidence, never approval

  🧑‍⚖️ reviewer      the fresh-context judge: mechanics, cold-read,
                   Openings in board order
                   🚦 CLOSE · REVISE · PROBE · DRAFT · HOLD
                   🚫 holds no write tools at all

                   Workflow, stores 🧾 _runs/ receipts, calls the auditor
                   🚫 never edits a page's prose
```
📌 Establishes that the three hands are one design, and that each one is defined by the act it is forbidden rather than by the act it performs.

#### 1.1 · The forbidden act is what makes the split load-bearing
(a producer that may approve its own output turns CHECK into a formality)
Every hand here could technically do the others' work, so nothing about the tooling enforces the split.
What enforces it is that each unit is dispatched into a fresh context with a different tool set, and the reviewer's set contains no writer.

#### 1.2 · The live units ship from `board/agents/`, and this page holds their snapshots
(one `.md` per agent, plugged into `skill/` and versioned there)
The snapshot is what this page's judgments are about, so a judgment can be read against the wording it was made on.
The shipped file is what actually runs, and when the two disagree the shipped file wins.

## Glossary
- 🤲 **hand**: one of the three dispatched agents that perform a page's phases when no person is in the loop.
- 🧾 **receipt**: the record a RUN stores under `_runs/page/`, saying what the controller did and what each hand returned.
- 🚦 **verdict**: the reviewer's only output, one of CLOSE, REVISE, PROBE, DRAFT or HOLD. It is never a repair.
