### Key points

- Claude Code 会话中,caller 频繁抛细节问题,容易把原定 topic 带偏,回过神已 lose control。
- 只依赖 session,没有留档,开会与日常工作难以串联,大任务(数据/feature/algo)之间也难解耦。
- 交接痛点:讲不清 context、拆不清子任务、别人无法接手继续跑。
- 作者用一个 HTML board 承载多 question:每个 question 是一页 slide,含 question 描述、downwind(完成条件)、now(进展)、discussion、comments、log。
- Board 由 py 脚本从 markdown 生成 HTML,可在浏览器或 Codex 内打开,支持每 question 独立 context 的对话入口。
- 认为最重要的是 question 的定义与完成条件(边界),这才是开会应对齐的核心,而不是具体执行细节。
- Board 应升级:加时间戳与人员署名、Related Files section、link 到 Excalidraw canvas 和 Claude 会话 summary。
- Excalidraw 使用建议:每个 board / question 单独一个 canvas,避免所有内容堆在一张画布上,便于聚焦与截图分享。
- 认可 board 作为"论坛/操作台"的定位,可跨 project 汇总未完成任务,防止 deadline 前才发现。
- 中文文本(如"跑马条""写盘跑通")可读性差,后续统一改英文。

### What the meeting decided

Each of these belongs on the page that owns it; routing them is a separate pass, and this list is the record it works from.

- 采用"一个大话题 = 一个 board,一个 board = 多个 question slide"的组织方式作为团队协作载体。
- 每个 question 页面必须包含:question 描述、downwind/finish condition、items to finish、now/进展 log、discussion、comments。
- Board 内容改为英文书写,以提升可读性。
- Excalidraw 采用"每 board/每 question 独立 canvas + 从 board 页面 link 过去"的方式,不再共用一张大画布。
- 作者先完成模板并 push,团队随后 pull 试用,不等基础功能尽善尽美。
- 删除/添加 question 等高级交互放到后续迭代,不阻塞首次发布。

### 3 · 🧱 板子的组成结构 `[15:17–20:40]`

> 💡 **Gist:** 📋 每个 board 由若干 question 组成，每个 question 有 intro / now / definition of done / example / why here 五块。

> **🛠️ S2：** 我怎么把它组织起来的？——它本身就是一个 HTML。当初的过程是：我问 Claude Code 说"我要开发这样一个 skill，但请先把开发这个 skill 需要的问题定下来"，就像一个大 project，先把哪些问题固定下来。
>
> **🛠️ S2：** 后来这些问题就沿着定好的问题来一个一个解答。第一系列（A）是把一块板子定下来；第二部分（B）是没有 skill 情况下怎么把内容写出来；再往后是把它做成一个 skill、怎么测试。做着做着我发现，板子可以直接连上 Claude Code 干活，所以又长出新问题。刚开始只有 3 个 question，越做越发现每个 question 会衍生新 question，所以 A 系列越来越多。
>
> **🛠️ S2：** 一块板子长这样——每个 question 是一个文件夹，PY 生成一个 HTML，图片也在里面。板子里有：
> - **Intro（问题描述）**：这一块是干嘛的。
> - **Now**：当前进度，跟 Claude 对话时它会更新到这里。
> - **Definition of done**：这个 question 结束要长什么样，比如照着清单能亲手搭一个新的。
> - **Example**：一个示范。
> - **Why here**：为什么放在这里（S2 自己也存疑这块用处大不大）。
>
> **🛠️ S2：** 核心 idea 是：一个大 topic 下拆成不同 question，每次跟 Claude 对话都是为了把这个 question 做出来，防止它跑偏。

### 4 · 🔗 单个 Question 页面 & 与 Claude Code 的对话回路 `[20:40–33:30]`

> 💡 **Gist:** 💬 每个 Q 页面既能加 comments/discussion，也能直接把 question 复制给 Claude 让它更新页面。

> **🛠️ S2：** 每一个 question 都是这种"单 Q slide layout"。你打开一个 Q 时页面长什么样、有多大、什么该出现——这些排版规则本身也是我在跟 Claude 对话中一点点定出来的（比如"不带框"这种要求它都记下来了）。
>
> **🛠️ S2：** 有个小槽点是 Claude Code 中文有时会写得很怪，甚至冒出日语、韩语。
>
> **🧑‍💻 S3：** 好像它还没训练够。

> **🛠️ S2：** 每一页下面有 checklist / discussion / comments / allow / log 几块：
> - **Checklist**：什么时候算完成，S2 觉得这个应该放到上面，相当于 progress。
> - **Discussion**：整体级别的意见。
> - **Comments**：inline 注释，选中改论文式的那种。
> - **Allow**（术语/解释表）：像"跑马条""聚焦""顶部压扁的头部撑什么什么"这种。

> **🧑‍🎓 S5：** 嗯，我感觉 Claude 做文字叙述性的东西还是没有那么精准。

> **🧑‍💻 S3：** 还有个问题：Q slide 或 web page 一打开时，没有立刻交代 what is this / why we need to、什么是它的 boundary、什么是 checklist——对新读者太不友好。

> **🛠️ S2：** 对，这种 comments 加法比较静态，它并没有跟你真正交互。你也可以让它 judge 你的 comments。
