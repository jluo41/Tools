JL, verbatim, twice and visibly frustrated: "what is the problem? what you are doing?" and later
"what youare doing? what happned?"

Both times the trigger was the same: a long autonomous stretch of reading tex, compiling, editing
assets, with no checkpoint. And both times the honest answer had to include "the files are changed
and the board is not rebuilt yet", which is an inconsistent state the user had no way to see.

The rule: on a long autonomous stretch, checkpoint before the user has to ask. When asked, lead with
STATE rather than narration: what is done, what is verified, what is half-done, and where you were
interrupted. Name the inconsistent state explicitly when one exists.

Related, and it also happened twice: JL asked for a list and got analysis first.
"we will not use display01b, please list what displays we will have here." Then, later,
"please list what displays you are using now?" A list request is answered by the list, first.
