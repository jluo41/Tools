Page 是什么怎么开始与 BoardPage-run
A page you can keep working on

从一个文件，
到可以持续修改的页面。

把 HTML、Markdown 或一份说明交给 haipipe-page，让它拥有自己的文件夹、可编辑的源文件和可阅读的网站。需要组织更多页面时，再把同一份 Page 接入 Board。

看 page-run 怎样一步步修改 ↓
01 / The page

Page 是作品，文件夹是它的工作空间。

你看到的网页是展示结果。真正可继续修改的内容和资源，保存在 Page Folder 中。页面的四个部分各回答一个问题。

OPENING · 定位

这是什么，为什么值得看？

用一段话说清主题、用途和范围。比如这份指南帮助你理解 Page 的使用方式，不承担 API 文档的全部细节。

OUTLINE · 规划

准备怎样讲清楚？

把需要表达的要点和支持材料组织起来。正式 Outline 从规划记录生成，不另手写一份重复目录；简单文件导入可以先没有规划。

CONTENT · 内容

实际交付了什么？

真正的解释、例子、图表或导入文件都在这里。你现在读到的这份中文指南，就是此 Page 绑定的 HTML 内容。

AIMS · 验收

怎样才算完成？

每个目标都有完成标准和当前事实。“页面已生成”不等于“读者已经理解”，更不等于“用户已经确认”。

02 / From file to page

给一个文件，然后在它自己的空间里继续做。

例如你说：“把这份 HTML 做成一个 Page，后面我还要继续改它。”

创建 Page Folder

导入文件副本和支持的本地资源，保留原始输入。Opening 和 Aims 提供页面外层说明。

编辑并预览

改内容就改对应源文件，改样式就改 HTML/CSS。工作站点可提供 Source 编辑器；静态网站只供阅读。

选择交付方式

生成静态网站，或启动可持续工作的 Page 服务。只有实际可访问的服务，才叫已经托管。

一个可带走的文件夹

my-page/
├── page.toml          入口与内容绑定
├── my-page.md         Opening / Aims
├── outline/
│   └── evidence/materials/
│       ├── input.html 可编辑内容
│       └── assets/    所需资源
└── delivery/web/      生成的网站
ONE EDITABLE SOURCE

改源文件，不改导出副本。

静态网站可以重新生成。若直接修改导出目录，下次构建可能覆盖修改。

网络字体、动态请求、数据库和后端不会因为导入一个 HTML 就自动打包。独立 Page 不代表任何应用都能离线运行。

03 / Together, without duplication

Page 管内容，Board 管组织。

两者能一起工作，是因为 Board 引用同一份 Page，而不是再复制一个可编辑版本。

PAGE

我这一页说什么

自己的源文件、资源、Opening、规划、Content 和 Aims。没有 Board，也可以构建并阅读。

BOARD

这些页面怎样放在一起

分组、排序、导航和组说明。挂载 Page 后提供统一入口；移除成员关系不应删除 Page 内容。

当前接入限制：Board 发现范围仍在自己的源目录下。任意外部或相邻文件夹的挂载，并不是已经实现的能力。
04 / Working together

Page-run：把“再改一下”变成可接续的过程。

一次 Run 围绕一个明确目标。你的一次反馈形成一个 Step；已关闭的一轮讨论重新开启，才进入下一个 Version。换聊天窗口，不应该丢掉已确认的内容。

下面是可点击的教学示例，不是真实运行记录。选择步骤只切换说明，不调用 agent、不修改源文件，也不记录你的确认。自动 Run 记录与确认界面仍待实现。
示例 · 等待反馈

目标：让新读者理解这个 skill

你的原始输入 · 示例
“先写 Opening，让别人知道这个东西可以拿来做什么。”
系统应当怎样处理

保存原始要求和修改范围，写出候选 Opening，再把实际保存的文字展示给你。不能只说“已修改”。

本步应留下什么

原始输入、完整候选文字、源文件身份、检查结果，以及下一步等待什么反馈。

三个词，三种尺度

Run：把 skill 介绍写清楚这一件事。

Version：围绕这个目标的一轮讨论与确认。

Step：某次反馈，以及它带来的结果。

每一步都有修改边界

你说“改 Opening”，不等于允许重写整个 Page。你说“Opening 定了”，也不等于整页验收通过。出现外部编辑时，应核对当前源文件，不能覆盖新修改。

以这份指南为例，下一步怎样推进？

你可以这样提要求修改对象完成标准
“Opening 再短一点。”页首介绍返回完整改后文字，其他部分保持不变。
“把 Board 的关系画得更清楚。”第 03 部分说明同一份内容、两个入口，不暗示复制同步。
“先把真实的 page-run 接上。”Run 功能实现真正保存输入和结果，支持跨会话恢复；需要实现与测试，不能靠示例按钮代替。
05 / What works today

哪些能用，哪些还在下一步。

能力当前情况这份页面是否提供
独立 Page 创建与静态构建已有 Page CLI是。本指南由 Page runtime 构建。
Page 工作服务与源码编辑已有独立服务能力本链接只提供阅读，不开放在线写入。
Board 组织同一份 Page已有源目录范围内接入未登记 Board 分组；由独立 Page 只读服务托管，不依赖 Board 运行。
Run / Version / Step 记录协议已有 agent 执行规范指南解释协议，不宣称已开启真实 Run。
自动记录、差异浏览、确认控件待实现没有。上方仅为教学示例。
“结束这一轮”为什么不等于“整个 Page 完成”？

本轮可能只确认 Opening。Content、证据、其他 Aims 或交付检查仍可能没有完成。每次关闭都需要说清范围，不把局部同意升级成整页通过。

真正的 page-run 至少要保存什么？

目标与范围、你的原始反馈、修改前后完整内容、每条反馈的处理结果、已确认文字、当前步骤和下一步。历史记录追加保存；当前进度由这些记录恢复。

我现在应该怎么继续改这页？

直接在这次对话里指出位置和要求，例如“把第 04 部分的 Step 2 改得更具体”。本页面没有自动收集评论；只有你实际发来的反馈才会进入后续工作。
