# Paper Run Specs and controls × Space

This is the read-only Paper view of the canonical definitions in
`haipipe-paper-workflow/ref/run-workflow.md`. Rows describe Specs and controls;
they are not allocated Runs. The five Spaces show where to orient or enter
owner work. Actual Ticket/Result identities and current status stay in the
separate native Run inventory and owner records.

**Access labels:** `Start here` means ask the named owner Skill in chat after
checking prerequisites; it does not start work from this table. `Shown here ·
read-only` means this Space presents source or status without changing it.
`Not built` marks an unavailable writer. In the Run Space, `⧉ Copy Run request`
appears only where a Paper judgment target is bound to an exact Idea, C5 claim,
C7 obligation, or C8 narrative row. It carries the Board/Page/item, instantiated
Spec and Run Type, owner, prerequisites, typed matching Run/status, and expected
receipt. It copies prompt text only; it never sends, starts, allocates, or writes.
The existing `⧉ chat` remains a separate source-grounded discussion/context
snippet. Page, Evidence, Delivery, Support, Compile, and Response cells remain
prompt-free while this Paper view cannot verify their exact owner/worker,
scope/format, target, or gate inputs.

If a user explicitly requests a Run prompt in chat, bind it to the selected
Board/Folder/Page/Evidence Item and target, canonical Run Type and Spec, owner
and selected worker Skills, prerequisites/gates, any matching native Run and
its status, and the next owner-permitted action. Name missing fields and route
HOLD when prerequisites fail. Only offer a prompt when the named owner
workflow supports commissioning that Run. Returning or copying prompt text
never sends it, starts a Run, allocates an ID, or writes a record.
