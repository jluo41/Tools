# haipipe-paper — Behavioral Preferences (portable)

Global "how to work" preferences for this skill, kept HERE under git so they survive a machine change. The `~/.claude` auto-memory is machine-local and does NOT sync across computers; this file does (it travels with the Tools submodule). ALWAYS read and honor these in a paper session.

These are global BEHAVIORAL preferences (how the agent should act), NOT skill defects — defects go to the `feedback/` inboxes. Entries are added by `/haipipe-paper digest` / `feedback` when a global pref is flagged, or by hand, using merge-or-create (one entry per topic; update, don't duplicate).

## Preferences

- **Communicate via ASCII diagrams, not walls of prose.** Show plans, options, and "my thinking" as emoji-rich ASCII (boxes + arrows); keep prose to a one-line ask. Preview confusing figures/displays as a `/diagram-ascii` sketch rather than a dense paragraph. (also mirrored in auto-memory: feedback_communicate_via_diagram_ascii)

- **Always run the REAL probe in the PROBE phase — never substitute an inline scan.** Evidence work has exactly ONE exit: the PROBE phase worker (`Skill("haipipe-paper-probe")`) and its FIVE-STEP LOOP. Raise each question as a SECTION in `1-probes/PPNN_<topic>.md` (① ORGANIZE), ② MATCH it against the bank's QA corpus, ③ DISPATCH only what MATCH could not close — the section's `q-executor:` block, VERBATIM, to `Agent(haipipe-task-orchestrator-agent)` / `Agent(haipipe-discovery-orchestrator-agent)` — then ④ POINT (`target:` → the answering QA file) and ⑤ INTERPRET (`a-consumer:` + the 1b-claims.md flip). A light web scan woven into the stage prose is a DRAFT-phase scoping aid, NOT a probe. A stage whose probe file has no section with a RESOLVING `target:` has not run its PROBE phase, and must not be promoted past it. MATCH comes before DISPATCH: most sections should close on T2 REUSE, so a q-executor is the exception, not the norm — but "the bank already answered it" is a MATCH result you must SHOW (the QA file you read), never an excuse to skip the loop. JL, 2026-07-07 (Paper-CGMtoCyclePhase seed): caught the empty probe folder and said "you need to always run the real probes in the probe phase." (also in auto-memory: feedback_always_run_real_probes)

- **Route data/artifact work through the haipipe-task lifecycle agents, not a generic subagent.** When paper/probe work needs a data artifact built (parse aggregated logs into a table, run a regression, materialize a display), dispatch it via `haipipe-task-orchestrator-agent` (Plan -> Build -> Execute -> Report with creator/reviewer gates and a reproducible task-folder), NOT a generic `general-purpose` subagent that edits the artifact directly. Reserve a plain subagent for non-task work (broad reads, recon, doc edits). Route is probe -> task. (also mirrored in auto-memory: feedback_data_work_via_haipipe_task_agents)

- **Prefer short, clean, complete sentences; do NOT cap the number per paragraph.** Readability wins over sentence count. Each sentence carries one idea in plain words; a long or multi-clause sentence should be SPLIT into several short complete sentences (never choppy fragments). Do not enforce a 4-5 or ~6 sentence ceiling at the expense of clarity. Avoid semicolons and em-dashes. Applies to abstracts, minimap sentence-points, and write/edit prose. JL, 2026-06-25: "we can have more sentences ... I want short and clean sentences rather than long and complicated sentences." (supersedes the earlier ~6-sentence cap; the anti-fragment half of feedback_compress_not_split still holds: split into COMPLETE short sentences, not fragments.)

- **No manual line wrapping in the markdown I write.** In every markdown file I author (SKILL.md, CHECKLIST.md, feedback inboxes, memory, docs), let each paragraph and each bullet run as ONE long line; never hard-wrap prose at ~70-80 chars. Code blocks and LaTeX source keep their own line structure. (also in auto-memory: feedback_no_manual_line_wrap)

- **Commit each tex edit as a change-log entry.** Every time JL asks to edit a paper `.tex`, after applying (and recompiling), `git commit` the specific edited file(s) on the paper's own repo/branch with a descriptive message (what changed + why), so the edits form a revertible change log JL can track. Commit ONLY the files deliberately edited, never the whole working tree (it carries unrelated display/compile churn); one commit per edit turn, not per Edit call; end messages with the `Co-Authored-By` trailer. A blind PostToolUse/Stop auto-commit hook is intentionally NOT used because the working tree holds unrelated uncommitted changes. (also in auto-memory: feedback_commit_each_tex_edit)

- **Manuscript sections use `%% ---- Pn.Sn ----` sentence indexing (JL: "the most important thing").** Every `0-sections/*.tex` is written as `% Para [id] Role -- point` banner + one `%% ---- Pn.Sn ----` marker per manuscript sentence (one sentence per marker), with `P` restarting at `P1` per file (file-local numbering). This mirrors the minimap's `I.Px / M.Px` sentence-points 1:1, so every manuscript sentence is individually addressable for the comment / values / citation / review passes and crosswalks cleanly to the minimap. When writing or restructuring a section, convert it to this form; do not leave free-flowing multi-sentence prose under a bare `% Para` banner. (also in auto-memory: feedback_manuscript_pn_sn_indexing)

- **No prose without understanding: explain what each sentence DOES before writing it.** The agent must not produce prose (manuscript sentences, story-line drafts, paragraph rewrites) unless it can explain what each sentence does for the reader and why it says THIS and not something else. Production without understanding (知其然不知其所以然) is the root cause of bad writing: the output reshuffles bullet points into plausible-sounding text without grasping the argument. If unable to explain the sentence's job, say so rather than draft. One sentence at a time, grounded in what it DOES, not what it CONTAINS. (JL, 2026-06-26, MISQ-Introduction session: "What is the root cause, in philosophy")

- **Prefer the simplest grouping that captures the point; do not over-split into clever multi-cell taxonomies.** When organizing conditions, claims, options, or findings, reach for the coarsest grouping that still explains the data before inventing finer distinctions. A 2x2 or multi-cell framing that separates items the user sees as ONE group is usually over-engineering; collapse to the simpler grouping unless the finer split clearly earns its keep. JL, 2026-06-26 (MISQ-Introduction): proposed a "two roads to null" 2x2 separating headache and cancer (and flagged recaptioning a figure to split them); JL replied "I think cancer should be together with headache?" and the simpler grouping (both = no opioid discretion) was correct. (kin to the anti-over-split spirit of compress-not-split / one-idea-per-sentence.)

- **NO TOMBSTONES — a skill doc states the CURRENT contract, never its history.** When a rule, file, field, or mechanism is retired, ERASE EVERY TRACE of it from the SKILL.md / ref / template: no "retired 2026-07-19", no "(previously X)", no "X is no longer used", no ban-lists naming the dead thing, no "this used to be a `mode: full` conditional". State only what IS. History belongs in the CHANGELOG (with the ruling quoted verbatim) and enforcement belongs in the checker; a doc that carries its own archaeology makes the reader reconstruct a timeline before they can act. This OVERRIDES the instinct to leave a ban so the next agent does not re-create the dead thing — that job is the checker's, not the prose's. JL, 2026-07-19 (paper/2-phase refactor): "不需要留退役告示,直接抹除任何痕迹" then "follow this rule to do all the following changes."

- **Bold the field labels in Q-consumer question blocks.** In any stage's Q-consumer `## Q-<Stage>-<n>` block, write the three field labels in bold — `**Description:**`, `**Reason:**`, `**Answer:**` — instead of the template's plain `Description:` form, for scannability. Applies at every stage that carries a Q-consumer (seed, claims, pitch, ...); the block body and the empty-at-DRAFT `Answer` rule are unchanged. JL, 2026-07-18 (Paper-Personality2Opioid seed re-align): asked to keep the bolded labels and record the convention as feedback.
