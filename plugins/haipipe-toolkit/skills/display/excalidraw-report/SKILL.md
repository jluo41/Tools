# /excalidraw-report · a report picture that reads at a glance

A report drawing is what the reader takes in before the words: it must show where things
stand and how one step leads to the next without the reader tracing lines (JL 261004: "I
don't like this from left and from right workflow, could you make it as concise and readable
as possible?"; "make the report draw to be very easy to read and make the logic flows to be
very very clear"). It is the picture a CoWork or Task report Page links under `### Evidence`.

```text
one file  ─▶ frame "Status"  │ frame "A vs B"  │ frame "Flow"      (frames side by side)
frame     ─▶ HEADLINE = the answer (46px) · one gray subtitle
            BIG BLOCK ─▶ BIG BLOCK ─▶ BIG BLOCK      (3 or 4 phases, no wrapping)
            ORANGE CALL-OUT: what still needs doing  (short chips)
            ZONE 1 (first in time) ─▶ ZONE 2 ─▶ ZONE 3 ─▶ STILL TO DO      (top to bottom)
zone      ─▶ ① label   one gray line of detail                [who]
            ② label   one gray line of detail
            …         (numbers on one vertical spine)
bottom    ─▶ Sources · click a label
```


Rules
-----

0. **Salient first: the three-second test.** Zoom the render out to a quarter. The reader must
   still get the message from four things: one headline sentence that IS the answer (about
   46px, at the top), at most three or four big coloured blocks, the step or item words in
   large type (24 to 30px), and one orange call-out for what needs attention. Everything else
   is small gray detail under those words. If every line is the same size, nothing is salient
   and nobody zooms in (JL 261004: "with a glance of look, we get nothing, nothing is salient.
   people then lost the interest to zoom in").
1. **One reading direction.** A flow runs top to bottom down one spine of numbered circles.
   Never a row that wraps back to the left ("left to right, then back" is the failure this
   skill exists for). A single short row of at most 7 stages, left to right with arrows, is
   allowed for a progress track; it never wraps.
2. **One line per item.** A label of 1 to 3 words in ink, then one line of detail in gray.
   No paragraphs in boxes; if an item needs two lines, it is two items or its detail belongs
   in the report text. Keep every line short enough that it never touches its zone's edge.
3. **Zones in the order things happen.** Before → during → after → still to do, each a
   coloured box with an uppercase title (`BEFORE THE VISIT · the team`). A zone holds rows,
   not cards.
4. **State by coloured dots.** Green done, orange to do or decide, gray later or the same,
   red problem. The key under the subtitle lists only the colours this frame uses.
5. **Who acts is a tag.** A small pill at the row's right end (`coordinator`, `JL`,
   `Research IT`); rows without a tag are the reader's own steps.
6. **One file per report, one frame per view.** A new view (a comparison, a status board,
   a flow) is a new named Excalidraw frame in the same file, placed to the right of the
   last one; never a second drawing file for the same report (JL 261004: "the same draw file
   with a new frame should be okay").
7. **Real names and numbers.** The same file, field, count and date as the report; no
   invented labels. Sources go at the bottom as clickable labels (`text(...)["link"] = url`).
8. **Generated, never edited.** The drawing is written by `studio/_build/build_<name>.py`
   and rebuilt by `studio/_build/make.sh`; the `.png` sits beside the `.excalidraw`. Change
   the script, rerun, never touch the output (AGENTS.md rule 13).
9. **Linked from the report.** The report's `### Evidence` lists the `.excalidraw`; the
   workbench then shows its `.png` in the Report column and opens it in the pop-out. A
   drawing nobody links does not appear (the Q04 picture was missing for this reason).
10. **Checked by looking.** Render, open the PNG, crop each zone, and fix any text that
    overlaps, runs past its box, or is crossed by an arrow; count the frames in the JSON.
    A render that comes back blank is usually the Excalidraw module download: retry once.


Draw
----

Copy the helpers from an existing builder in the same Block (each builder carries its own
copy, as in `b11_azure_account/studio/_build/build_v3.py`) and add the frame-aware pieces:

```python
els, n = [], [0]
FRAME = [None]                      # every element drawn after frame() belongs to it

def base(kind, x, y, w, h, **kw):   # ... "frameId": FRAME[0], ...
    ...

def frame(fid, name, x, y, w, h):
    els.append({"id": fid, "type": "frame", "name": name, "x": x, "y": y, "width": w,
                "height": h, "frameId": None, ...})
    FRAME[0] = fid

def line1(x, y, color, label, rest, size=18):      # one row: dot, label, gray detail
    dot(x, y + 3, color); text(x + 30, y, label, size, INK)
    text(x + 30 + (len(label) + 2) * size * EM, y, rest, size, GRAY)

STEPS = [("Invite", "coordinator adds the participant's email", "coordinator"), ...]
path(79, Y0 + 20, [[0, 0], [0, DY * (len(STEPS) - 1)]], GREEN, width=3)   # the spine
for i, (name, detail, who) in enumerate(STEPS):
    y = Y0 + i * DY
    circle(60, y, 40); text(80, y + 9, str(i + 1), 18, GREEN, align="center")
    text(120, y + 8, name, 21, INK); text(300, y + 10, detail, 18, GRAY)
    if who: pill(1690, y + 20, who, ORANGE)
```

Rebuild one drawing and look at it:

```bash
source .venv/bin/activate
H=<Block>/studio; T=$(mktemp -d)
python $H/_build/build_<name>.py $T/<name>.excalidraw
python $H/_build/render_excalidraw.py $T/<name>.excalidraw $T/<name>.html $T/<name>.png
cp $T/<name>.excalidraw $T/<name>.png $H/
```

Worked examples (Project-Samsung, b13_smartwatch_connector/studio/_build/):
`build_connector_path.py` frame "Patient phone setup" (zones in visit order, steps 1 to 8 on
one spine, coordinator tags) and `build_q03_status.py` (frame "Q03 status" with a one-row
progress track, frame "Health Connect vs Samsung Health SDK" as a two-column comparison with
a dot per cell).


Boundary
--------

`excalidraw-section` maps a paper's structure from its Draft plans; this skill draws a
report's picture from what the report says. The report's words belong to `haipipe-page` /
`haipipe-question`; the workbench that shows the picture is `haipipe-workbench-cowork` or
`haipipe-workbench-task`.
