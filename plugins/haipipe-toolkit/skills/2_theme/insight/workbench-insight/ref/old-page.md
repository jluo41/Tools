## 📡 The board · 🔎 Insight Board

One dataset, four Spaces; `ref/insight-board.md` has the contract. Insight ›
Questions is one table per partition in three columns: Logic, the questions
asked at Data, Information, Knowledge and Wisdom, by level and number (no
QD/QI/QK/QW codes on screen); Work, the runs that answer them: each evidence need with what the answering page's
`answers.yaml` binds to it, then only the runs those needs use (a page without
bindings falls back to its `runs/` tickets, then to each task config's
`answers:` line); Report, the answering page itself, labelled "page <id>"
(`haipipe-insight` `ref/report.md`). Check Space reads handoff eligibility
from exact owner receipts (`insight_handoff.py`, `workflow/handoff.yaml`) and
never grants it.

## 🧬 An Insight Block

An Insight Block (`../haipipe-insight/ref/block-contract.md`: a task Block with
`workbench: insight`, one Job per level, one Task per question; JL 261005) is drawn by
the same renderer: `servers/workbench-insight/instance_reader.py` reads it into the
snapshot the board already renders, one dataset at a time (`&dataset=<name>`, the first
in board.md by default), and nothing on screen changes; Home opens it here, not in the
Task workbench. A question's Logic cell shows its carried short question and name, and
More shows the ask, Why now, What would answer it, any other carried field and its live
needs; the Dataset view shows `meta/meta.md`; a cell's mark is computed by
`haipipe-insight-check` `ref/check_block.py`; a Work line opens one run
(`<dataset>_<partition>`). Its Report cell is that run's generated report
(`reports/<run>/report.md`, JL 261005): the first lead lines, opening the
run pop-out, and the question's page under it as "answer: page <id>". The run
pop-out shows the report first (lead lines, figures, tables), the receipt folded.

## 📚 Scope and Prototype

The Spaces follow the shared order Guide → setup → work → Delivery
(`servers/workbench/README.md` § Space order). Two Spaces set up: **Scope**,
this board's own data (Dataset · Partitions · Questions, with the Ask box), and
**Prototype**, the Block's design: its questions and their code (JL 261003; the Space keeps
its name, the design now sits in the same Block, JL 261005). Scope comes
first: the data, then what is asked of it and by which code, then the answers.

The Prototype Space (`instance_reader.prototype_views`) has five Views:

1. **Meta**: the Block's name and title with four numbers (live questions, live needs,
   questions with a script, datasets); one table by level's Job (questions, needs, scripts,
   retired); the partitions in words; the shared settings; the design files, shared code folded.
2. **Data · Information · Knowledge · Wisdom**: the Job's opening question and its
   `level.md`, then one folding row per live question: id, name, the short question, and
   chips for partitions asked, script and sign-off. Open, a row shows the ask,
   Why now, What would answer it, the needs table and its files. Retired questions fold
   at the bottom with what replaced them.

The family's methods and papers are not board data: they live in the shared Guide. The
Prototype Space's Runs panel lists the design runs in method order (carry a board over,
register a cut, review the questions, plan the evidence, write and review the script).

## 🎨 Prototype › RoadMap Draw

The Insight Space's Views are its partitions, Full to Cross (JL 261003); it has no
Studio View. The working drawings belong to the Block (`studio/`). The first row is the question map, generated by `haipipe-insight`
`ref/question_map.py` from the question files: it shows view only, with no Edit drawing,
and says when a question file is newer than it (rerun the script). The rows after it are
any other drawing in `studio/`. There is no Add drawing form (JL 261003). It follows the shared Workbench design
(`servers/workbench/README.md`, "Task alignment"): a freeform list of folding
rows, one per `studio/<name>.excalidraw` beside the Block's `board.md`, with no
drawing type, template or metadata. A row's canvas loads when it opens, view only;
Edit drawing hands it the pen and Finish editing gives it back; Open full screen opens
the same file; open rows are remembered in the browser tab. The scenes are opened and
saved by the shared Studio routes (`workbench/xcal.py`), never by this
presenter, which stays read-only. A static build lists the drawings without a canvas.

## 🧭 Guide

The shared Guide Space (`servers/workbench/guide_families.py`, family
`insight`) sits before Scope and explains the family only, the same on every board, in
four Views:

1. **Description**: what the Insight Workbench does, its skills and its Spaces.
2. **Method**: one page as the Design family's (Guide's own step list is skipped):
   the methods drawing (`servers/workbench-insight/guide/methods.excalidraw`, editable; written by the author
   script `Tools/blueprints/b11_theme_insight/studio/s03-insight-methods/methods_drawing.py` from the cards and papers,
   as Design's), then
   `servers/workbench-insight/guide/method.md` with the six steps as its spine: 1 · the six steps (one table:
   what happens, where in the workbench, who decides), 2-4 · steps 1, 3 and 5 in depth
   (question-asking, question-answering and question-results reading methods, each
   with its decision tree and cards),
   5 · checking (T0 to T8 at their steps, the evidence), 6 · why it works, and the
   Reference. Every section, the drawing first, is a fold card in the Guide's RoadMap style;
   the six steps open, the rest closed, so the page opens as its outline. No Chinese in
   titles. Served by `/_board/insight-board?embed=methods&view=method`.
3. **RoadMap Draw**: the whole design drawing
   (`Tools/blueprints/b11_theme_insight/studio/s02-insight-workbench/insight-workbench-design.excalidraw`), view only:
   skills and runs, the workbench, where things live, how a question is asked. Its
   generator is the drawing's only writer.
4. **Related Paper**: `servers/workbench-insight/related/papers.md` as paper cards, served by
   `embed=methods&view=papers`.

The folder map resolves inside the Block (`meta/`, `j0N_<level>/tNN_<name>/`). Guide
never signs a question change or a handoff. The Block's own drawings are in Prototype ›
RoadMap Draw.

## 🪟 Pop-outs, no page-level workbench

A run line opens one ticket's result (receipt, QA notes, its figures above its
tables, files); a page opens as a document. Both open over the board and keep a "new tab" link.
The 🔎 drawer tab on a page opens the same page document (JL 261001: the run's
results are the answer; no page-level UI).

## 🔗 Pairing

`servers/workbench-insight/` is this skill's served face; the two pair by
name, `workbench-insight` with `workbench-insight`, like every other
row of the table in `servers/README.md`. `/w/<board>` resolves to
`/_board/insight-board` when `board.md` declares `board-kind: insight-board`
(or the folder is laid out as an InsightBoard). `file=` may be omitted; the
