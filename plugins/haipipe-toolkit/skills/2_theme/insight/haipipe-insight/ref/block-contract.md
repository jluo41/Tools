# Insight Block · the question owns its code

> **Older layout (261008).** A new insight topic is a Prototype and an insight Board: read
> [insight-ladder.md](insight-ladder.md). This contract stays for Insight Blocks made before it (one Job per DIKW
> level) until each is carried into a release (`prototype_from_block.py`). Its § The question file and § The script
> are still current: the ladder keeps both and only moves where they live.

Read when making, growing or checking an Insight Block. An Insight Block is an
ordinary task Block (`haipipe-task`, Block range `b5N_<topic>_dikw`) whose board.md
says `workbench: insight`: one Job per DIKW level, one Task per question. It replaces
the Prototype + Instance pair (two boards, a copied set of scripts, a lock and a sync,
retired JL 261005) and, before them, the method-cut task Block with `answers.yaml`,
config `answers:` lines and the hand-kept register grid (`board-contract.md` keeps that
oldest layout for boards made before it).

Why one question, one task: when the code that answers questions is cut by method (one
"rates" task serving ten questions), each new question is fitted to an existing run, its
spec is written from that run, and a check that compares the two cannot fail. Here each
question carries its own code, so a run can only answer the question it sits in, and the
code exists once.

## The Block

```text
work/b5N_<topic>_dikw/
├── board.md                    board-kind: task-block · workbench: insight
│                               datasets: {<name>: <extract .parquet under the SPACE root>, …}
├── meta/
│   ├── meta.md                 what the extract holds: grain, window, sources, limits
│   ├── partitions.md           every partition, its filter, in order, and why it exists
│   ├── thresholds.yaml         shared floors, alphas, seeds · power.smallest_effect_pp
│   └── status.md               the question × run grid, written only by the checker (--write)
├── src/                        functions shared across levels, when two levels need one
├── studio/                     the Block's drawings (the workbench's Prototype › RoadMap Draw)
│   ├── question-map.excalidraw generated by ref/question_map.py: every live question, its reuse arrows
│   └── <name>.excalidraw       hand sketches, one file each
├── j01_data/                   D · what the extract holds
│   ├── level.md                     the level's opening, writing rule and law (prose)
│   ├── src/                        functions two or more of this level's scripts share
│   └── t01_<name>/                 the question D01: one Task Folder = one Page Folder
│       ├── question.md             the question: YAML block, then prose
│       ├── scripts/<name>.py       its one entry script (SPEC line), helpers beside it
│       ├── t01_<name>.md           THE PAGE: the short answer, across its runs
│       ├── draft/                  the page flow's plan, Evidence Items, records/, previous/
│       ├── runs/
│       │   ├── <dataset>_<partition>.sh   one ticket per dataset × partition it is asked on
│       │   └── run-<kind>-<MMDD>-<slug>.md  the page's own runs (write, check), from page.py
│       ├── results/<run>/          what that run computed: runtime.yaml · partition_power.csv ·
│       │                           the spec's files · fig_*.png · provenance/ (the exact spec and scripts)
│       └── reports/<run>/report.md the run's report, generated from its results
├── j02_information/t01_<name>/ …   I · rates, contrasts and segments inside a partition
├── j03_knowledge/t01_<name>/ …     K · tests across results: pool or split, cross-fit, replicate
└── j04_wisdom/t01_<name>/ …        W · counsel, tested before a person signs it
```

- **Question id** = `<L><NN>`: L is the level of its Job (D in `j01_data`, I in
  `j02_information`, K in `j03_knowledge`, W in `j04_wisdom`) and NN its task's number
  `tNN`; `question.md` carries the same `id:`. NN numbers a level's questions from 01,
  once, never reused; `<name>` is a few lowercase words joined by `_`. A need is
  `<L><NN>.E<n>` (`I03.E1`).
- **A run is `<dataset>_<partition>`**, and there is no per-run config: the dataset names
  an extract in board.md `datasets:` (a name with no underscore), the partition a filter in
  `meta/partitions.md`. Every ticket has the same lines; `ref/scaffold_block.py <Block>`
  writes one per dataset × asked partition for every question with a compute need, and
  never overwrites one. A new extract is a new dataset in the same Block: its runs sit
  beside the others and the code is not copied.
- **The task rules of `haipipe-task` hold**: one stem for ticket and result, a receipt
  written before the work and finalized after its gate, heavy output in
  `_WorkSpace/ProjectResult/` with a `heavy.yaml` pointer, paths relative to the SPACE
  root, review by an agent that did not write the code.
- **The studio** is the Block's. `studio/question-map.excalidraw` is generated by
  `ref/question_map.py <Block>` from the question files: one frame per level, one box per
  live question, one arrow per `cite` need from the reused question to the question that
  reuses it, a dashed box for a question linked to no other. Rerun it after any question
  changes; never edit it. A hand sketch is its own `studio/<name>.excalidraw`.
- A theme inside a Block (funnel, time, geography) is a `group:` field, never a code folder.
- **The workbench**: Home opens a task Block with `workbench: insight` in the Insight
  workbench (`/_board/insight-board?board=<Block>[&dataset=<name>]`), one dataset at a time,
  its partitions as the Views.

### meta

```text
meta.md          the meta page: what the extract holds, its grain, window, sources, limits
partitions.md    every partition, its filter, in order (YAML), then the reasons in prose
thresholds.yaml  every shared value (floors, alphas, seeds) and power.smallest_effect_pp
status.md        generated by the checker; never edit it
```

```yaml
---
partitions:
  - {name: full, where: []}
  - name: alpha
    where: [{column: <col>, eq: <value>}]
  - {name: cross, of: [alpha, beta]}
---
```

`full` is required and unfiltered. `cross` holds no rows of its own: a cross
run receives every listed partition. Operators: eq, ne, lt, lte, gt, gte,
isin, notin, notna. A filter that selects no rows refuses the run. A partition
may carry `plain:` words; the prose below the YAML says why each partition
exists and how its bounds read.

### The question file (v2)

The question keeps the words its asker wrote. Every field below except the
partitions block and the needs' output map is prose, carried as written.

```yaml
---
id: I03                            # <L><NN>: its Job's letter and its task's tNN
level: information                  # data | information | knowledge | wisdom
question: who is in the population?          # the short wording a reader scans (the Queue's)
name: Patient Demographics                   # five words or fewer, the task's <name> in slug form
ask: <the full question, one sentence>
source:                            # where it came from, when it was carried (optional)
  board: ../<old board>            #   register, old id, Gen-1 cell, the old cells and where it stood
  register: MT02-question-information
  id: QI3
  cells: {full: 🟡 I03-full, alpha: 🚫 full-only}
partitions:
  asked: all                       # all | [full, …] | cross
  not_elsewhere: <why>             # required unless asked is all
  power: none                      # or {test: rate_precision | two_proportion | script, outcome: <col>,
                                   #     groups: <col>, alpha, target_power, effect: <pp>, effect_reason: <why>}
needs:
  E1:
    kind: compute
    what: <what a run must produce>
    pass: <what a result must contain to count; admits a null>
    cut: the cell's partition      # | the whole extract | cross
    unit: <what one row is>
    measure: <the quantity>
    by: <the grouping or the contrast>
    uncertainty: <the interval or test, or none: exact counts>
    rivals: <the rivals adjusted for, or none>
    output:
      <file>.csv: [<column>, …]          # columns in order
      metrics.json: [<dotted.key>, …]    # a json file may be shared by several needs
  E2: {kind: cite, what: <what is borrowed>, from: D01.E1}
  E3: {kind: judge, what: <the reading>, from: [E1, E2]}
  E4: {kind: compute, what: …, retired: <why>}   # history: kept, never run, never cited
agreed: ✅ 261002                  # ⬜ until an agent that did not draft the needs agrees them
---

<Name>
======

**Why now**: <why the board asks it now: what waits on it, what it replicates>

**What would answer it**: <the evidence in words, before any need>

**<any other field the register carried>**: <as written>
```

Rules, checked by `haipipe-insight-check` `ref/check_block.py`: question,
name, ask, Why now and What would answer it are present; every live compute
need has the nine spec fields; kinds are legal at the level (D compute; I
compute, cite; K compute, cite, judge; W compute, cite, judge); a cite names a live need
one level below (the same level only from a cross question); a judge reads live
needs. A need is never edited once a result is bound to it: it gets
`retired: <reason>` and a new id.

**A signed change** (the question review proposes, a person signs) is applied without
editing any carried word in place:

```yaml
# a need replaced: the old need stays, a successor need gets the next id
  E3: {kind: compute, what: …, retired: "split into D05 (signed ✅ 261002)"}
  E5: {kind: compute, what: …, supersedes: E3}
# a question replaced (split, merge, move, reworded ask): the old file stays as history
retired: moved to Information as I19 (signed ✅ 261002)
superseded_by: [I19]                 # [] when nothing replaces it
# the new question names where it came from
source: {from: [D04], signed: ✅ 261002, review: <the review file>}
changes:                             # every signed change to a question, in order
  - {signed: ✅ 261002, change: <the signed line, as worded>}
```

A retired question is asked nowhere, has no live needs, keeps no scripts, and is not on
the workbench; its ids are never reused. New and changed needs start `agreed: ⬜` until an
agent that did not draft them agrees them.

**What the check does not do.** It never adds a need to cover a word of the
ask, and it never rewords an ask. Whether a question is good is the question
review's (`haipipe-insight-question` GI1, Q1-Q7): the check only flags
suspects as notes (Q1 the ask joins two questions, Q2 a need no judge reads,
Q4 a cause word in a Data or Information ask, Q6 two questions compute the same
table). A reviewer proposes keep, split, merge or move; a person signs a
change; the old question is retired with a reason, never edited in place.

**Can it generalize to a partition?** `partitions:` answers it in two halves,
both written before any result exists:

```text
meaning   logic: inside a partition, is it the same question? A question about the
          extract itself (full-only) or about whether to segment (defer) is asked on
          full only, with not_elsewhere saying why; a field constant inside a
          partition is reported as untestable, never dropped
power     data: can this partition's rows answer it? The runner computes the minimum
          detectable effect (MDE) from the partition's n and base rate, BEFORE any
          outcome contrast; answerable when the MDE is at most the smallest effect,
          the Block-wide thresholds.yaml power.smallest_effect_pp unless the question
          sets power.effect with its reason
```

Never judge a partition by whether its result is still significant: that
selects partitions by their outcome, and a difference in significance is not
a significant difference. The page reports each partition's estimate with its
interval; whether partitions differ is a cross question.

### Making a Block from a register board

A board made the register way (`board-contract.md`) already holds its
questions' meaning. Carry it, never redraft it:

```text
1  carry     ref/carry_over.py <old board> <Block> --dataset <name>=<parquet> --report <md>
             writes board.md, meta/ (meta, partitions, thresholds), each level's level.md
             (the register's Opening, Queue and Law) and one question.md per register
             division, word for word; ids Q<L><n> → <L><NN>; a LOGIC refusal (full-only,
             defer) is not asked there, a DATA refusal (thin, no measure) is asked and the
             run refuses it again or answers it
2  verify    carry_over.py --check: every field equal and every division rebuilt byte
             for byte from the new file; a second run writes the same bytes
3  review    the question review (Q1-Q7) proposes; a person signs each change
4  scripts   per question, from its live needs: the output files and columns are the
             old ones, so the new results compare with the old board's
5  tickets   ref/scaffold_block.py <Block>
```

### The script

```python
"""<L><NN> · <one line>. Writes exactly the question file's output files."""
SPEC = "<L><NN>"                  # the question it answers; the runner checks it
COLUMNS = ["<col>", …]            # the extract columns it reads, "all", or "none" (it reads only results)

def run(df, ctx):                 # cross questions get ctx.partitions = {name: df} and ctx.full (the whole extract)
    ...
    return {"<file>.csv": table, …}
```

A script reads no path, writes no file, names no dataset and no partition. It
may call `ctx.refuse(reason)` when its probe shows the extract cannot answer
(the cell becomes 🚫 with that reason), and `ctx.constant(column)` to learn
whether a column is constant in this partition, and `ctx.beside(<file>)` for a
file the extract's preparation wrote beside it (its manifest, its data
dictionary); `ctx.extract` is the extract's path. `ctx.wilson`, `ctx.holm` and
`ctx.thresholds` (meta/thresholds.yaml) are provided. `ctx.result(<QID>, <file>)`
reads another question's ok result in this Block (the same dataset and partition; `full`
for a cross run): how a Knowledge script tests across results and a Wisdom script tests its
counsel. The receipt records each file it read (`reads:`), and a change to one makes
the run STALE. Functions two scripts
share sit in the Block's `src/` (or a level Job's `src/`) and are imported by name; every Job's `src/` is
importable, the question's own Job first, and the receipt follows every module a script imports.

## Runs, reports and the page

- **Every level is a run** (JL 261005): ask, work, report. Data counts, Information
  compares inside a partition, Knowledge tests across results (pool or split,
  cross-fit, replicate), Wisdom tests its counsel (holds on held-out data, under a
  changed assumption, with enough sample for the next round). A Knowledge or Wisdom
  script reads the level below through `ctx.result`, never the rows again. A question
  with no compute need has no run; its page answers it.
- **The run report is THE report, and it is generated** (`reports/<run>/report.md`,
  by `ref/run_question.py` with `ref/figures.py`): per compute need its plain lead lines
  first (rounded), then its figures (`results/<run>/fig_<need>_<table>.png`, drawn
  from the result tables only, never the rows), then its pass line and its tables
  (rounded; `results/` keeps every digit), and the power table last. A table is drawn by
  its shape (rates with intervals, message x level, stability, balance, missing, share,
  and an estimate beside its interval, the shape of most Knowledge tests);
  an unknown shape gets no figure. It is never written by hand; rerun the ticket.
- **`content_since`** in the receipt is when the spec's tables last changed. A rerun that
  writes the same tables keeps it, so the page's `results-read:` and a CHECK made since
  stay current; the checker compares against it, not against `ended`.
- **The page is the short answer** that reads the run reports: what the question found,
  in plain words, pointing at each run's report and figures for the evidence. It is what a
  CHECK judges, and at Wisdom what a person signs. One per question, one section per run
  (datasets in board.md order, partitions in partitions.md order; a run the question is not
  asked on has no section), written through the `haipipe-page` flow
  (`ref/write_answer_page.py`, `page.py adopt`, a CHECK by another agent). Its Evidence
  Items name the need (`**Need**: I01.E1`) and the run's file (`results/<run>/<file>`). A
  sentence that two partitions differ needs a test, so it belongs to a cross question. The
  header carries `question:`, `partitions:` (its runs) and `results-read:`; there is no
  `state:` line.
- **A cite** reads the cited question's file by its path from this folder
  (`../../j01_data/t01_<name>/results/<run>/<file>`).

## The run

`runs/<dataset>_<partition>.sh` calls `ref/run_question.py <task folder> <run>`. In order:

```text
1 resolve   task folder → its Block, Job and question.md; the dataset and partition from the run
2 receipt   results/<run>/runtime.yaml: running · ticket · block · extract · sha256 of the spec,
            the scripts, and the shared files the run rests on (partitions.md; only the src/
            modules its scripts import, followed through their imports; only the thresholds.yaml
            sections its code names, plus power for a powered question); provenance/ copies
3 load      COLUMNS + the filter's columns, from the dataset's extract ("none": no extract)
4 filter    the partition's where (cross: every listed partition)
5 power     partition_power.csv, from n and the base rate, before any contrast;
            not answerable → status refused · reason underpowered
6 script    run(df, ctx) → tables; ctx.result reads of other questions are recorded (reads:)
7 gate      the files and their columns equal the spec's output lines; no column is a row
            key the extract carries; no table has a row per input row
8 write     the tables and their figures; receipt ok · ended · duration · outputs · figures ·
            tables_sha256 · content_since; reports/<run>/report.md
```

A gate failure writes no table and leaves the receipt `failed` with the
problem; the report still says so. Heavy output, when a question has any, goes
to `_WorkSpace/ProjectResult/<Project>/<Block>/<Job>/<Task>/<run>/`.

## Status is computed

```text
—              the question is not asked on this run's partition
🚫 <reason>     the run refused: underpowered (with its MDE), or the probe's reason
🟡             the run is ok, but the page is missing, unchecked, older than the run's
               content, or cites nothing of this run
✅ <YYMMDD>     the page's latest CHECK closed CLOSE after this run's content_since,
               results-read: is not older, and every need is cited
STALE          the spec, the scripts, meta's partitions or thresholds, a src/ module the
               scripts import, or a result it read (reads:) changed since the run (sha256)
```

A page CHECK is run by an agent that did not write the page, read-only; its
verdict is recorded with `ref/record_check.py <page> <VERDICT> <review file>`,
which opens and closes the page's check Run and, on CLOSE, approves the plan
(a v0 plan is promoted to v1.0).

Nobody types a cell. `haipipe-insight-check` `ref/check_block.py <Block>` prints
the grid, the notes and the problems (`--write` also writes `meta/status.md`), and
exits 1 on any problem; with `--strict`, also on any 🟡 or STALE.
