# Report Style Profile

Drafting guide for formal stakeholder report artifacts.


## Voice examples

**Executive summary (executive audience):**
```
Bottom line: <the design> increases <the outcome> by
8.2pp (95% CI: 4.1–12.3pp) among <the group>. Projected
annual <value>: <amount> across the current <population>.
Recommended: evaluate expansion to <the eligible group>
in <quarter>. (See Source 1.)
```

**Regulatory finding (regulator audience):**
```
3.2 Effectiveness

The intervention showed a statistically significant
improvement in <the outcome> (OR = 1.42, 95% CI:
1.18–1.71, p < 0.001).¹ The effect was consistent across
<subgroups> (Table 2). No adverse events were reported
during the pilot period.

¹ Source 1: the accepted signed handoff and its bound Supporting/Local Run Result,
  recorded by path in the Job's inputs/ fence.
```


## Drafting rules

1. Structure depends on audience:
   - Regulator: exec summary → methodology → findings →
     limitations → recommendations → appendix
   - Executive: bottom line → evidence → ask
   - Partner: context → joint findings → next steps

2. Every factual statement maps through the Job's inputs/ fence (its manifest).
   - Regulator: footnote (¹ Source 1: ...)
   - Executive: endnote
   - Partner: inline parenthetical

3. Tables and figures with captions required for data claims.

4. Limitations section mandatory for regulator audience.

5. Length per audience:
   - Regulator: ≤ 1500 words
   - Executive: ≤ 600 words
   - Partner: ≤ 800 words


## Audience pairing

```
audience=regulator   → formal, footnoted, comprehensive
audience=executive   → direct, outcome-oriented, brief
audience=partner     → professional, collaborative tone
```


## Self-review checklist

```
[ ] Structure matches audience template
[ ] Every factual claim maps through the Job's inputs/ fence (format per audience)
[ ] No stale or superseded handoff/source is presented as settled evidence
[ ] Length within budget for audience
[ ] Limitations section present (regulator)
[ ] Data tables/figures have captions
[ ] Job and Task ids, the pinned goal · method · inputs, and the Run's result/ paths resolve
[ ] Any render manifest binds the exact source and picture inside its Run's result/
```
