# M05 · m3

from m2: ① names the agent's tool. `aggregate_query.py`, beside this file in the registry, is the one door to the raw
extract that the dictionary names: the agent asks, the tool answers with grouped counts and rates only (identity
columns refused, free text only as its length, a time only as its hour, weekday, date or month, a group under 11
hidden, at most 60 groups shown), and writes each answer as `q<NN>.yaml` in run-reason-t00's `result/queries/`
with its receipt (the tool's sha, the dictionary's sha, the extract's sha). At most 30 queries, all within
run-reason-t00. The agent never opens the extract any other way and never reads another method's input.

A reasoning step that rests on an answer says `from: query q<NN>`. The fence check accepts it when `q<NN>.yaml` is in
t00's `result/queries/` and its receipt names this tool and the extract and dictionary of the Job's manifest. ② to ⑤
as m2: the input ladder's common steps.

M05 m3 is the benchmark beside the input ladder (M01 m2 · M02 m2 · M03 m2 · M04 m3): it sees the goal and the raw data
through its own analysis, none of our insight.
