# Labeling UI rules

## A01 · One Block page

**Rule:** A Block owns the page and shared Report / Studio / Jobs framework. Jobs, Tasks, Runs and Studio topics
are selections within it. Use canonical records and guarded writers; a missing selector stays an explicit gap.
**Check:** Open a requested Task through its Block and confirm the Block title and route remain.

## A02 · Shared Bands, owned content

**Rule:** Bands group folds; Studio Type definitions specify content. Shared readers supply each Blueprint's Band
names and order. Labeling references Work's common definitions and creates only needed theme-specific types.
Task procedure instances retain their owning skills and files without a separate shared type definition. Empty
Bands and absent type-definition groups are omitted; Studio folds open independently. No Job type becomes a Band.
**Check:** b15's structure builder verifies the shared reader's Band mapping, order and emitted groups.

## A03 · Rules and examples together

**Rule:** Block Structure keeps Structure / Draw / Skills and catalog-generated applicable Job types / Task types
views. Folder, Job-Task and Studio content each keep their
verified examples with them. Structure uses the shared collapsible folder tree for every subject and example.
Draw’s Job-Task and Studio use separate shared drawings; Folder retains its tree. Both read the same names and relationships. Use the shared file reader
and preview dot. Variable names use `〈 〉`;
fixed names come from contracts. Skills reads the owning files. Do not infer stored work from a design preview.
**Check:** The builder requires folder trees and no mindmap in every Structure fragment, separate Draw bindings,
sources, placeholders and preserved parent/child relationships. Browser acceptance opens the tree branches,
examples and skills from the owning Block.

## A04 · Current contracts in skills

**Rule:** Skills state current instructions, authorities and implementation limits. Keep superseded decisions and
version narratives in Block Trace or Git, outside skills. Preserve active engine identifiers and callers. Update
any generating source before rebuilding a derived file. Apply README's fresh-context invocation check.
**Check:** Review the complete changed skill for historical narrative and verify its instructions against current
code and an actual example. Do not claim a planned contract or adapter is implemented.

## A05 · Type catalogs describe evidenced contracts

**Rule:** Each Block Structure instance has `types.md`: Job group type, Job type, Task group type, Task type,
for/holds, actual fields and owning skills. Declare absent levels and unresolved identifiers without inventing
types. Shared `block_types_pages.py` generates the applicable views. Actual Work Studio Bands come from that
Block’s bands or topic Tags; Blueprint Bands cannot stand in for them. Preview-only examples prove no execution.
**Check:** Require every expected catalog, nonempty evidenced Task types and exact generated pages. Report missing
Job identifiers, grouping decisions, input adapters and shared-checker gaps separately from presentation results.
