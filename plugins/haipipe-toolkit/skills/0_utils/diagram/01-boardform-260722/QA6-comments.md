## Question
怎么像 Google Docs 那样，在页面上选中一句话就地加评论？而且这条评论要同时活在 `.md` 和 `board.html` 里，不是只存在浏览器里。

## Done when
- [ ] 选中一句 → 写评论 → 它真的落进 `.md` 文件里
- [ ] `.md` 里那条评论用眼睛就能读懂，不是一串坐标或哈希
- [ ] `board.html` 上被评论的那句高亮，评论挂在旁边
- [ ] 原文被改动之后，评论要么跟着走，要么明确标成「锚点丢了」
- [ ] 没有 JS 时评论照样显示（只是不能新加）

## Now
现在只有**段落级**评论：在 `.md` 的 `## Discussion` 里写一行 `> JL: …`，页面上排成一条带色边的评论行。
够用，但太粗 —— 只能说「这一题我有意见」，说不了「就这一句说不清」。

真正的难点不是弹框，是**锚点**。一条评论必须能在原文被改过之后还知道自己挂在哪。
Google Docs 靠一套文档模型解决，我们只有纯文本文件。用「把原句抄进去」当锚点最可读，代价是原句一改锚点就断 —— 所以「断了要能被发现」必须写进完成线。

还有一件事要先认下来：**这是这块板第一次真的需要 JS**。拿不到选区就做不了这个功能。
但可以只让「新加评论」依赖 JS，「读评论」仍然是纯 HTML —— 页面永远不会因为没有 JS 而变白。

## Why here
JL 从第一天就提了「板要能加自己的评论」。段落级已经有了，句子级是它自然的下一步。
而且这一题定的是 **`.md` 里的存储语法** —— 语法不定，QB1 的 SKILL.md 就没法写「怎么在板上评论」。

## Glossary
选区 API：浏览器里「用户当前选中了哪几个字」这个信息，只有 JavaScript 能读到。
File System Access API：浏览器直接读写你本机文件的能力。Chrome / Edge 在 `localhost` 上可用，用户点一次「允许」之后就能写回 `.md`。
CriticMarkup：一套写在纯文本里的批注语法，`{==这句==}` 表示被标记的原文，`{>>评论<<}` 表示评论。好处是 md 里肉眼可读。
锚点：一条评论「挂在哪句话上」的定位方式。
