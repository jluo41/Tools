# `brief` · create or resume the Application Brief

1. Resolve the Application root and read `board.md`, current Pages, and venue packs.
2. Find the canonical `folder-kind: brief` Folder. If absent, create `<DesignTopic>-DesignBoard/0-BR-brief/BR00-brief/BR00-brief.md` through `haipipe-folder` + `haipipe-page` and load `haipipe-design-brief`.
3. Reject `page-type: brief`, D0/GD0, and PageX shapes; there is no Brief migration route.
4. Define opportunity, audience set, behavior/outcome, venue scope, promise, and the insight needs this board raises, each with a stable id.
5. Freeze already authorized signed-W inputs by exact path, Page version,
   content hash, signature, and GI6 receipt. Route every unsettled need to the
   matching MT register and derived `partition × DIKW target` Question Group;
   Brief never commissions upstream evidence.
6. Write the initial Design Page roster, one row per audience × behavior job × primary venue. The InsightBoard's Meta Page rosters which Insight Page took each raised need.
7. Run the Page workflow through release and fresh CHECK, or hold on named needs.

Return the Brief path, raised need ids, Question Groups, frozen signed-W inputs,
Design roster, and next Page phase.
