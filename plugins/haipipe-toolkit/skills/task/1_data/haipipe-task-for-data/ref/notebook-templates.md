Notebook Template → Task Instance Pattern
==========================================

Each task `.py` is an **exact copy** of a template from `code/scripts/haistepnb/`.
The template is copied as-is to the task folder and renamed.
CONFIG is overridden at runtime by papermill (`-p CONFIG <path>`) or `run.sh`, NOT by editing the `.py` file.


Templates (ABC naming)
-----------------------

```
code/scripts/haistepnb/
  a1_source_nb.py      Stage A1 — SourceSet from raw csv/parquet
  a2_record_nb.py      Stage A2 — RecordSet from SourceSet (multi-partition)
  a3_case_nb.py        Stage A3 — CaseSet from RecordSet (multi-partition, parallel)
  a4_aidata_nb.py      Stage A4 — AIDataSet from CaseSets (multi-partition merge)
  b_model_nb.py        Stage B  — ModelInstance (train + examples + validate)
  c_endpoint_nb.py     Stage C  — Endpoint_Set (package + test payloads)
```


Instantiation
--------------

```
Template                              Canonical Task worker
────────────────────────────────      ──────────────────────────────────────────
haistepnb/a1_source_nb.py        →   bNN_.../jNN_.../tNN_source_.../scripts/source.py
haistepnb/a2_record_nb.py        →   bNN_.../jNN_.../tNN_record_.../scripts/record.py
haistepnb/a3_case_nb.py          →   bNN_.../jNN_.../tNN_case_.../scripts/case.py
haistepnb/a4_aidata_nb.py        →   bNN_.../jNN_.../tNN_aidata_.../scripts/aidata.py
haistepnb/b_model_nb.py          →   bNN_.../jNN_.../tNN_model_.../scripts/model.py
haistepnb/c_endpoint_nb.py       →   bNN_.../jNN_.../tNN_endpoint_.../scripts/endpoint.py
```

To instantiate:
1. Copy the template to the task folder (exact copy — do NOT edit CONFIG)
2. Place it as `tNN_<task>/scripts/<worker>.py`
3. Create `scripts/config/rNN_<run>.yaml` with project-specific settings
4. Create `runs/rNN_<run>.sh` that passes CONFIG via papermill

CONFIG is injected at runtime:
```bash
papermill template.ipynb output.ipynb -p CONFIG examples/.../tNN_<task>/scripts/config/r01_base.yaml
```


Task Group → Template Mapping
-------------------------------

```
Task type      Template           Pipeline stage
────────────   ──────────         ──────────────
data           a1/a2/a3/a4_*_nb   Source→Record→Case→AIData
fit            b_model_nb         Model training (with ExampleConfig)
endpoint       c_endpoint_nb      Endpoint packaging
```


Source vs Output
-----------------

```
tNN_<task>/scripts/<worker>.py              ← SOURCE
tNN_<task>/notebooks/_source.ipynb           ← generated template
tNN_<task>/notebooks/rNN_<run>.ipynb         ← execution record
```

The `.ipynb` at the task root is a template notebook generated by `run.sh` step 1 (`convert_to_notebooks.py`).
It is NOT source — do not edit it.
The notebook under `notebooks/` is the papermill execution record with cell outputs.


Partition parameters
---------------------

Stage A2-A4 templates include these papermill parameters:

```python
# %% [parameters]
CONFIG         = "..."
REPO_ROOT      = ""
NUM_PARTITIONS = 0      # 0 = use config / auto-discover
PARTITION_INDEX = ""    # "" = all; int = one partition (1-based)
NUM_WORKERS    = 1      # >1 for parallel (Stage A3 only)
```

Inject via papermill:
```bash
papermill template.ipynb output.ipynb -p CONFIG ... -p NUM_PARTITIONS 20
```


CLI scripts (alternative to notebook)
--------------------------------------

Each stage also has a CLI script with full partition support:

```
code/scripts/haistepcli/
  source.py     python code/scripts/haistepcli/source.py --config <config>
  record.py     python code/scripts/haistepcli/record.py --config <config> --num-partitions 20
  case.py       python code/scripts/haistepcli/case.py   --config <config> --num-workers 4
  aidata.py     python code/scripts/haistepcli/aidata.py --config <config>
  model.py      python code/scripts/haistepcli/model.py  --config <config>
  endpoint.py   python code/scripts/haistepcli/endpoint.py --config <config>
```

The CLI and notebook use the same underlying pipeline code.
Choose CLI for scripted pipelines; notebook for interactive inspection and Databricks.
