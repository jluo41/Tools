# /haipipe-page-for-stage · one explicit link in a non-Paper lifecycle

Load `haipipe-page` first. A Stage Page is valid only when it declares an exact,
live `stage-contract:` path owned by its Board or family. This generic variant
does not resolve a global Paper stage index and contains no per-stage craft.

## 🚫 Current Paper exclusion

Current Paper work never creates `S-Open-*`, `S-Work-*`, `S-Main-*`, or an
S01-S10 chain. Resolve Paper intent to one of its six owned types:

```text
stable paper identity       → Seed
one external target         → Venue
venue-specific paper map    → Narrative
one reader-ordered unit     → Section
one feedback cycle          → Round
one regenerated family view → Dash
```

An old Paper S Page is migration input, not a live runtime. Read only what is
needed to move its durable decision or prose to the owning current Page, record
the source, and do not create a new sibling Stage Page.

## 📄 Grain

One Stage Page owns one explicitly chained product in a non-Paper lifecycle.
It closes only when its human gate passes.

```text
requires:       upstream Page ids whose accepted outputs are required
style-from:     Page or contract that supplies writing constraints, when any
provides:       exact artifact or decision handed downstream
stage-contract: exact live contract path owned by this Board/family
```

The Board registry order is never dependency inference. The four fields above
make the chain explicit.

## 🧱 Managed Stage Contract

The owning Board machinery may materialize a managed span from the declared
fields:

```markdown
<!-- haipipe:contract:start sha256=… -->
### Required Inputs
<one row per requires, with accepted version and provided artifact>

### Writing Style
<resolved style-from constraints, when declared>
<!-- haipipe:contract:end -->
```

Generated material stays between markers; authored explanation stays after the
end marker. A stale source hash is reported and regenerated by the owning
family's explicit sync action, never silently during a read.

## 📚 Content is the product

`## Content` holds the real stage product, not a status report about producing
it. Supporting material goes to the base Page frame:

```text
upstream and style bindings → Stage Contract
durable targets             → Aims
current facts               → States
source and output paths      → Files
history and decisions        → Log/Law
```

The owning `stage-contract:` defines the product-specific Content outline. If
that path is absent, dead, archived, or belongs to the retired Paper runtime,
the Page is HOLD and may not be drafted.

## 🔁 Page workflow

Stage remains a Page Type, not a separate phase engine. Run the shared Page
workflow:

```text
SHAPE ⇄ SURVEY ⇄ LAND ⇄ EMBED (the OUTLINE part) → WRITE → CHECK (the DRAFT part)
```

Probe retains its shared PageX and QA lanes. A Stage contract cannot override
human-only citation verification, probe read, display acceptance, outline
approval, or final CHECK authority.

## ✅ Closing checks

- `stage-contract:` resolves to one current, non-archived owner contract.
- Every `requires:` Page and accepted version resolves.
- Content is the declared product and `provides:` names it precisely.
- Aims and States correspond one to one.
- Downstream work reads the checked artifact/version, not registry position.
- A person, never a machine, records the Stage gate.

This variant owns no scripts and no roster. The owning family supplies any
stage-specific sync/check machinery. The archived Paper-era version of this
contract is preserved beside the other retired Page Type material and is not a
current route.
