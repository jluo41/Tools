# The plugin roster · one row per name

The single list of page-plugin names (design.excalidraw, JL 260815).
A subfolder of a page's home folder is board material only if its name is here.
`kind`: PRIMARY = originals a person makes, committed; DERIVED = projections of the page's text, regenerable, gitignorable.

**Probe is a logical family over two existing plugin rows, not a third folder:**
`pagex/` is its accepted-Page lane in OUTLINE; `probe/` is its Task/Discovery
QA lane in PROBE/EVIDENCE. Their storage stays separate so an accepted Page
binding can never masquerade as a bank answer.

Writers for the DERIVED document trio live in `skills/board/page-plugins/_shared-export/` (`md2tex.py`, `md2docx.py`, `docx2pdf.py`); the board calls them by path.
`--paper-root` is discovered by walking up from the page for a `0-*.bib`; a page outside any paper exports cite-less rather than refusing.
Per-plugin SKILLs ship under `page-plugins/` (JL 260815): draw · slide · chat · latex · word · bibex · probe · outline · skill · display · pagex · task · meeting · direction · design · render, each `haipipe-plugin-<name>` and delta-only over this contract; the roster stays the single list of NAMES, a row going 🟢 brings its skill with it, and logging/_fixture gain theirs when their rows go live.
TWO skills have no row on purpose, and for the same reason — they own no subfolder:
`haipipe-plugin-folder` (JL 260816) is the 📂 meta-surface OVER this list, and `haipipe-plugin-value` (JL 260819) is the 🧮 surface over the `## Values` blocks that already live inside probe cards. A number filed a second time is one thing filed twice; what was missing was never a folder but one more level of ADDRESS, `PP<NN>.v<n>`.
⚠️ `outline/` was absent from this table until 260821 while `<page>/outline/` had been real storage since 260817 — a gap directly against this file's own opening law that a subfolder is board material only if its name is here.
✅ Since 260824 the opening law is CHECKED, not just written: `check.py · check_plugin_roster` scans every page folder and reports `plugin-not-rostered` for a subfolder whose name is missing from this table. Three breaches in four days were three too many for a rule enforced by reading.
⚠️ `render/` repeated it: `haipipe-plugin-render` shipped 260820 pointing its Files section at "the row this plugin expands", and that row did not exist until 260824, when a design run wrote real `<page>/render/` storage and the absence surfaced. Twice now the plugin arrived before its name did, so the order is worth stating: the roster row comes FIRST, and a per-plugin SKILL whose row is missing is describing a folder the board is not obliged to recognise.
