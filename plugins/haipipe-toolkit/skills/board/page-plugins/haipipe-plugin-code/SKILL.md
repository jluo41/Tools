# /haipipe-plugin-code · the surface the code part will get

**LOAD `haipipe-plugin` FIRST.** A PRESENTER plugin (haipipe-plugin §🔌): no
roster row, no folder — the law lives in the roster's `scripts/` · `runs/` ·
`results/` rows and haipipe-page §📁's lower part. This file fixes the
surface's shape BEFORE the engine exists, so the first build has a contract
to fail against.

```text
⚙️ Code
├── 🎫 Runs        default: the ledger, newest first — one card per runs/
│                  ticket: what it called, when, exit state, the results it
│                  names; a script no ticket names renders as a 🎈 finding
├── 📦 Results     the results/ listing, each file with the probe card that
│                  binds it (PP<NN>.v<n>) or an "unbound" chip — never a
│                  preview of raw rows, results can be big and are not prose
└── 📜 Scripts     scripts/ + config/ and any lane-local script, read-only
```

## 🔒 What the surface must never offer

- **No run button.** Runs are launched by the person or a chat session under
  the ticket's own command (long jobs: tmux); a browser click that executes
  arbitrary page code would be a second door beside the one door.
- **No result editing, no PHI.** results/ is machine-written and regenerable;
  the tab frames, it never lands.
