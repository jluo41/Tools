# 分头标，只报有分歧的
state: 🟡 PARTIAL
owner: RA
method: 多个模型分头标 + 一条一条过

## Question
这 60 条谁来标？怎么标才不浪费你的时间？

## Diagram
```
  几个模型各自分头标同一条
        │
        ├─ 都同意 ──► 自动通过，记一笔（不惊动 JL）
        └─ 不一致 ──► 分四类：
                       真边界 / 规则没写清 / 冒出新情况  ──► 送 JL 面前
                       第四类（某模型手滑）＝噪声        ──► 自动处理
```

## Now
「揪分歧」的机制有：分歧分四类，只有前三类（真边界 / 规则没写清 / 冒出新情况）送 JL，第四类当噪声自动处理。
但实际跑的是**两个模型平级对标**，不是几个模型分头标；而且是**一次标一批** —— 毛病是前面几条的判断会把后面几条带跑。这条 JL 明确说要改。

## Done when
- [x] 揪分歧机制：分歧分四类，只有前三类送 JL，第四类当噪声自动处理
- [ ] 一条一条标（现在是一次标一批 —— JL 说要改）
- [ ] 几个模型分头标（现在是两个模型平级对标 —— JL 说要改）
- [ ] 一致的自动通过，并记一笔

## Why here
JL 会上两句话直接定了这一步：让几个模型分头标，目的是揪出分歧 —— 都同意的就跳过；而且要一条一条过，不能一次标一批。

## Glossary
噪声：某个模型偶尔手滑标错，不代表规则有问题，这类分歧不用惊动你。
