1 · 这个项目在做什么

   病人在网上写的医生评论
        ↓
   给每条打一个人格特质标签：宜人性 / 尽责性 / 开放性 …
   每个标签三档：HIGH · LOW · NONE
        ↓
   产出两样东西：一份标注规则（guideline） + 一批标好的数据

请真人标太慢太贵，所以用一组大模型代替一队人类标注员。

2 · 为什么这件事难

「这条评论体现了高的宜人性」—— 这是判断，不是事实。

两个真人看同一条评论，也会打出不同的分。

所以没有标准答案可以对照。

我们只能想办法证明一件事：我们标得跟真人一样好。

3 · 我们已经做到哪一步

   三个维度跑完了：
      B01  agreeableness   宜人性     κ = 0.937
      B02  conscientiousness 尽责性    κ = 0.937
      B03  openness        开放性     κ = 0.932

   κ（Cohen's kappa）＝ 两方打分有多一致的统计量。0 ＝ 跟瞎猜一样，1 ＝ 完全一致。
   0.93 在标注领域算很高。看起来很好。

4 · ⚠️ 但这个 0.93 不算数

   0.93 是拿哪些题考出来的？
      ⇒ 拿「规则作者自己看过、并且亲手标过」的那 24 条。

   同一版规则，换成没看过的题再考一次：
      B03_dim_openness   看过的 24 条 → 0.932
                         没看过的题   → 0.667      ⬅ 掉了 0.27

   ⇒ 高分只说明规则**记住了**那 24 条，
     不说明它在新数据上管用。

这不是某个人做错了，是方法上的一个洞：出题的人和答题的人是同一批。

5 · 出路：正确性只能从外面借

   公开数据集里有一类特殊的：
      它保留了**每一位**人类标注者的原始打分（per-rater），
      而不是只给你一个合并后的"标准答案"。

   ⇒ 于是能算出：真人和真人之间，彼此有多不一致。
     这个数字就是**天花板** —— 人类自己也就做到这个程度。

   ⇒ 如果我们的引擎能达到那个天花板，
     就说明它标得跟真人一样好。

   这个一次性的认证，原文里叫 autonomy license。
   要跑的那组公开数据集，原文里叫 battery
   （也是配置文件 ref-config.md 里的字段名：license: {battery: [...]}）。

⚠️ 注意 license 只需要拿一次，是引擎级的。

拿到之后，换任何新的构念（construct）跑，都继承这份可信度 —— 前提是新构念跟

battery 里的内容沾边，沾多远要如实写出来。

附录 A · 术语对照

   construct          构念 —— 你要标的那个东西本身，比如"开放性"
   guideline          标注规则 —— 一份写清楚"什么算 HIGH/LOW/NONE"的文档
   gallery            例子册 —— 已经标好并附了理由的样本，规则从它长出来
   κ (Cohen's kappa)  一致性统计量，0 = 瞎猜，1 = 完全一致
   human ceiling      人类天花板 —— 真人之间彼此的一致性，我们的上限
   per-rater          数据集保留了每一位标注者的原始打分，而不是只给合并结果
   battery            用来考引擎的那组公开数据集（ref-config.md 里的字段名）
   autonomy license   一次性认证：引擎在 battery 上达到人类天花板，
                      之后换新构念也继承这份可信度
   anchor / fixed set 固定的题，永不变，用来比较不同版本的规则
   held-out           每轮换新的题，规则没见过，用来看真实水平
   objective          挑构念候选时用的标准（downstream 或 discriminance）
   base rate          这个特质在语料里大概多常见
   panel              一组同时打标的大模型
   validator          负责验的模型，规定必须跟打标的模型不是同一个

附录 B · 引擎完整跑一遍是什么样

   0  先摸底         估算这个特质在语料里多常见（base rate）
   1  定构念         多个大模型各提一个候选定义 → 各标一批样本
                     → 按 objective 挑最好的那个 → 针对分歧再打磨
   2  打标           一组大模型打标；负责验的模型必须换一个
   3  改规则         用分类器找出模型最拿不准的样本 → 据此改规则 → 出新版本
   4  量成绩         一致性 + 稳定性 + 没见过的题上的表现 + objective 分数
   5  判收敛         objective 不再涨 且 规则不再变 且 没见过的题上掉得不多
   6  铺全量         用分类器 + 分层策略把整个语料标完
   ─────────── 以下是引擎级的，一辈子只做一次 ───────────
   L  拿 license     整条引擎跑一遍 battery，确认 κ ≥ 人类天花板

附录 C · 这台引擎已经修掉的 8 个方法学问题

来自 2026-07-17 那次会 + 2026-07-21 的独立复核，两边撞到了同样的结论。

代号 F1–F8 是 RA 在 note-update 里的编号，这里保留是为了对得上原文。

F1  出题的和答题的是同一批 → 每轮换没见过的题 · 验的模型换一个 · 正确性外部量一次
F2  在数据集 A 上验证，却宣称在 B 上成立 → license 只覆盖跟 battery 沾边的构念
F3  没有人类天花板 → 天花板从公开的 per-rater 数据集来，引擎级摊销一次
F4  "说得清楚" 不等于 "标得对" → 一致性 / 清晰度 / 正确性，三个数分开报
F5  向量空间里靠得近 ≠ 标签一样 → 难例改从训练过的分类器里挖
F6  专门挑出来的难例被当成了普通样本 → 代表性样本和难例样本分成两池
F7  每轮随机抽 24 条来打分 → 改成固定的题 + 每轮换新的题
F8  规则不再变 ≠ 规则是对的 → 收敛条件要加上"没见过的题上掉得不多"
