## 它解决什么问题

用户在实际截图、图片或视频帧上标注修改意见，也可移动和缩放识别出的矩形区域。工具保留原图，将坐标、意见、移动前后的位置等作为结构化反馈交给 Agent。像素区域的移动表达修改意图，不直接修改网页 DOM、源代码或自动补全背景。

项目组图用稳定的页面 ID 关联截图。每轮反馈关联当时的截图快照，正在评审的画面不会被下一次截图悄悄替换；提交时保留整组索引，只附有批注或布局移动的页面。空反馈表示没有提出修改意见，不等于功能验证通过。

## 技术与 AI 的分工

- 桌面：C++20、Qt6；原生截图、OCR 与视频等能力按平台实现。
- Web：HTML/CSS/JavaScript，提供独立离线页面。自动分块采用本地色块与边缘算法，有明确识别边界。
- Agent 连接：CLI、Web Agent、MCP/MCP Apps，以及 DSH 入口。具体宿主能否即时回传，需要实际验证。
- AI：默认由当前 Agent 理解图片与已提交反馈并修改源文件；可选的桌面 API 解析功能另行调用用户配置的模型服务。它本身不替代编码 Agent。

## 对 Question Book / Insight / Design 的建议

| 参考机制 | 建议用途 |
| --- | --- |
| 图上批注和几何移动 | 让非技术用户在真实 UI、图表、Studio 绘图和 slide 上表达具体修改意见 |
| 稳定 page ID 与快照 | 每条意见绑定 artifact ID、版本、view 和截图，避免修改到另一版 |
| 多页组图 | 一轮查看 Block、Job、Task 的相关页面，保持跨层界面一致 |
| 结构化反馈 | 在 Interaction/Review 记录一次，Plan + Results 引用处理状态及修改产物 |
| 明确提交后回传 | 用户提交才形成待处理工作，草稿、取消与超时不能自动变成修改指令 |

建议工作路径：实际页面截图 → 用户批注 → 归属层评审记录 → 对应计划项与执行记录 → 更新产物 → 新一轮截图核对。

同一条评审意见在 Task、Job、Block 通过身份引用展示；原始截图、反馈和源文件不为上层展示重复复制。新版本产生新的快照，并保留旧反馈指向的原快照。

评审意见、决定和 Finding 应分开：例如“把按钮移到标题旁”是一条修改意见；是否采纳是决定；从多次验证得到的可复用认识才可能成为 Finding。不能把每条批注直接计为研究发现。
