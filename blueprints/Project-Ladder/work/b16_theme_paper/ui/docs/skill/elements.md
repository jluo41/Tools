# Elements

What a delivery is made of, and how each piece is worked: the element types of the paper workflows. Each topic
below is one rule or view, with its requests.

## 🧊 Topic: Elements ▸ the bricks of a delivery

A delivery is made of elements (a Section of sentences and paragraphs). Each element has an address, a history of
versions, a rating by rubric, its decisions (how and why it changed), people's feedback, and marks; an unresolved
mark asks for attention. The AI loops on each element: rate, change, rate again, until it passes high, or it stops
and leaves a comment with its reason for a person. The AI settles the tedious marks itself and leaves only the
critical ones, the ones that need thinking (a river that washes the sand and keeps the gold). An element type is a
class (its rubric, loop and marks); each sentence is an instance. Defining the elements defines the sculpture.

Address in the paper theme: PaperBlock ▸ jNN version ▸ tNN draft Task ▸ Draft view ▸ Draft Lab ▸ sentence or
paragraph. Each workflow (paper-draft, paper-ideation, paper-story) needs its own element types written down.

This is the leaf of the three views (block/three-views.md): Folder is where an element is stored, Element is where
the page shows it, and Session is which episode changed it and why.

Proposed: one card per element type (address, parts, history, rubric, what the AI may settle, what it must raise,
marks), first for paper-draft (sentence, paragraph, display, citation, value), then ideation and story.
