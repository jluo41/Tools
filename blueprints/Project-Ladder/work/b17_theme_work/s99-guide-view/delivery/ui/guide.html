Using work pages

Block▶Job▶Task▶Run

A Block is one topic, its Questions answered by the Runs of its Jobs' Tasks. A Job is one line of work, its Tasks in the order they run. A Task is one folder that is also a page: it is planned, built and run, and holds its Runs.

Block · the Question and its report

  1. 1Ask the Questionthe question, what we expect and what would answer it; a different agent reviews it, a person signs it
  2. 7Write the reportOpening, Answer, Evidence, Limits, Next, each claim citing an exact Result
  3. 8Check and deliveran agent that did not write the report checks it; a person releases it

Job · one line of work

  1. Lay out the Jobits Tasks, in the order they run; each Task then takes steps 2 to 6

Task · planned, built, run and read

  1. 2Plan the Taskits contract, written before its code: what it reads, returns and how it is checked
  2. 3Build the Taskthe worker, its config and its Ticket, in the Task folder
  3. 4Review the codean agent that did not write the code reads it before the Ticket runs
  4. 5Run the Ticketonly the Ticket writes its Result and receipt; heavy output goes to its store
  5. 6Report the Runwhat the Run shows, read from its Result alone

When a check fails

It goes back to the step that owns the fault: a vague question to Ask, a wrong number to the worker and its Ticket (never to the Result), an unsupported sentence to Write. A Result, a receipt or a built page changes only by rerunning what made it.
