What a chat keeps

A kept chat is a list of QAs. One QA is one turn, in three lines at most; the detail lives in the files the turn wrote, and the QA points at them.

The face of a chat

What a QA keeps

PartWhatFrom the session file
questionthe person's words on one line, cut at 200 characterstheir message, and any message sent while the turn ran
→ answerone line, cut at 160the first line of the turn's last reply
⇢ outputsthe file names; the full paths are in paths:its Edit, Write and NotebookEdit calls

Left out: tool calls and their output, reasoning, injected context and the rest of the reply. A QA's address is cNN.qNN, so a page can mark the element a QA changed.

Rules

  1. Kept, not logged. Most sessions never become a cNN.
  2. Time order. The next free number; a number never moves and is never reused.
  3. Paths at the time. Written when the chat is saved, from the files the session itself wrote.
  4. No transcript. Only the QAs are kept; the session file stays where Claude Code keeps it.
  5. No work output. A drawing belongs in an sNN, a result in a Run's result/.
  6. Signed and frozen files are never written by the saver.

Saving one

new_chat.py new <block> --slug <slug> --title '<title>' --summary '…' \
    --from ~/.claude/projects/<dir>/<session>.jsonl --session <name>
new_chat.py refresh <block>/cNN_<slug> --from <session.jsonl>
new_chat.py list  <block>
new_chat.py check <block>

new_chat.py is the only writer of a cNN. A chat saved with --from is refreshed once each time an answer ends, by the Stop hook chat_hook.py, never mid-turn.
