# Resource notes

Keep one note per canonical source. Use `YYYY-MM-DD-short-title.md`, with the
date first collected; preserve that address on later visits. The Block's daily
index links to the note. Topic links point to that same note, not a second copy.

Use the following fields and omit sections that have no content:

```markdown
# Resource title

Collected: YYYY-MM-DD
Published or updated: source date, or unknown
Kind: paper / repository / article / tool / announcement
Topics: writing, review
Original source: primary URL, or what still needs to be found
Shared via: post URL or description of the supplied screenshot

## What the source says
Short attributed summary. Distinguish reported results from experience or opinion.

## What we checked
Files or passages actually read, version if available, and unresolved claims.
Keep the primary source separate from the social post describing it.

## How this could help
Specific application, overlap with current practice, and limitations.
Link to the relevant Blueprint and skill; do not treat collection as adoption.

## Follow-through
Next useful check and the owning Job or Task once it exists.
When a change is adopted, link its implementation and validation.
When it is declined, record the reason. Later assessments append a date.
```

Dates identify source events and collection history. They are not review scores.
Keep any screenshot or excerpt only as needed and preserve attribution. Do not
replace a primary-source link with a social-post summary. A source that cannot
be retrieved remains an intake lead, not verified evidence.
