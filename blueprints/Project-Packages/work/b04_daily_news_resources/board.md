## Topic

External articles, papers, repositories, tools and announcements that may improve
the packages and their blueprints. Capture a source when it arrives, assess what
it contributes, and link any adopted change back to the source.

The daily index uses the date collected. Each resource keeps its own publication
date, topic, primary source, assessment and destination. Repeated shares reuse
the same resource note. A new version gets a dated assessment in that note.

## How resources become work

Record the original source, what it says, why it matters here, and what remains
uncertain using the [resource note guide](resources/README.md). Distinguish an
author's experience, a study's result, and our proposed application.

A link or screenshot can be collected before its primary source is found; name
the missing source explicitly. Collection alone does not approve a rule or
install a tool. A proposed change links to the owning Blueprint's Job or Task;
after it is tested, the resource note links to the actual change and its evidence.
Formal source reading and synthesis use the Discovery workflow when commissioned.
Jobs and Tasks are created for that bounded work, not for every incoming link.
