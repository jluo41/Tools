# Authorization evidence and limits

The supplied task explicitly authorizes creation and editing of an isolated source and report under a unique /tmp directory, and preparation of a commission. It explicitly forbids FIELD dispatch, external services, browser/OAuth, credentials, providers, network, real user data, and repository edits. This is direct task authorization for those fixture operations; it is not an Insight standing authorization record.

No actual person-issued standing grant with a durable source address, board path, workflow_runtime_id, bounded target cells/Run IDs, permitted action list, expiry, and revocation evidence was supplied. Do not invent any of those fields or treat this fixture record as an active grant. A commission can be prepared without asking the real user again; applying a real standing grant remains untested.

For an actual Insight target, preserve the existing grant at <board>/_runs/insight/<workflow_runtime_id>/authorizations/<id>.yaml with schema haipipe.insight-authorization/v1. Transcribe only the existing person's decision, exact source, identity, authorized_at timestamp, board/runtime, target cells/native Run IDs, actually granted action subset, expiry, and current status. Never assign an approving identity or fresh approval timestamp on behalf of the person. Link the original evidence; a generated token is not approval.

Before each covered action, resolve source, person, board, runtime, target, action, expiry and revocation. Keep the normal owner and gate. Record the authorization path, exact action/target, licensing rule, evidence and result in the owning Folder log; index it in the runtime. A licensed partial-final settlement also quotes the licensing sentence and receives a reciprocal answering-Page receipt. No control-only action creates a decision Run.

Only explicitly granted actions among canonical-mark-spelling, derived-header-reconciliation and licensed-partial-final-settlement can be batched. They are maximum allowed classes, not defaults. Empty run_ids authorize no Run execution. A grant cannot sign a Wisdom handoff, release new Supporting computation, expand targets, bypass gates or remain valid after runtime closure/failure, explicit earlier expiry or revocation. A held runtime can resume within its original scope and time limit. Reuse valid supplied approval for the same operation; do not request it again.

The generic remote-error fixture has no Insight board or authorization schema. Do not transplant the Insight YAML record into its issue register, and do not treat Insight's mechanical grant as authorization to execute or edit an unrelated report program.
