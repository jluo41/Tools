# 〈Work Block (Knowledge)〉

- Folder <!-- folder -->
  - bNN_〈learning-goal〉/ <!-- block -->
    One coherent learning goal. Bands add no folders.
    - jNN_〈practice-goal〉/ <!-- jobs -->
      Create for executable practice; concept-only learning needs no Job.
      - tNN_〈execution-unit〉/ <!-- tasks -->
        Split only independently executable units.
        - runs/rNN_〈execution〉/ <!-- runs -->
          One execution's configuration, receipt and outputs.
          - result/ <!-- results -->
            Evidence of checked behavior, not a substitute for understanding.
        - tNN_〈execution-unit〉.md <!-- task-face -->
          Task objective, type, inputs and acceptance criteria.
      - jNN_〈practice-goal〉.md <!-- job-face -->
        Job objective, type, Tasks and groups.
    - sNN-〈learning-topic〉/ <!-- topics -->
      Beside Jobs, grouped into the five learning Bands.
    - related/ <!-- related -->
      Follow Related for retained sources; reference existing Discovery results.
    - trace/ <!-- trace -->
      This Block's requests, plan, approval, changes and checks.
    - board.md <!-- face -->
      Learning goal, scope, Bands and links to actual records.
- Job-Task <!-- job-task -->
  - 〈Work Block (Knowledge)〉 <!-- execution-root -->
    Organization rules; a concrete practice is proposed in A2UI s31.
    - 〈practice-group-name〉 <!-- job-group -->
      Job group type: 〈Practice theme〉. The Block bands: line binds a jNN range.
      - jNN_〈practice-goal〉 <!-- typed-job -->
        Reference Work code / check / doc by independently deliverable output.
        - 〈task-group-name〉 <!-- task-group -->
          Reference Make / Show. The Job bands: line binds a tNN range.
          - tNN_〈execution-unit〉 <!-- typed-task -->
            Reference applicable code / display structure; confirm the execution route separately. Runs keep configuration and results in runs/rNN_〈execution〉/.
- Studio <!-- studio -->
  - 〈Work Block (Knowledge)〉 <!-- studio-root -->
    Display order, not mandatory execution stages. Omit empty Bands and preserve existing IDs.
    - 📚 Resources · s0N <!-- resources -->
      Source-related topics belong directly in this first Band; no same-named Studio is required.
      - s0N-〈source-selection〉 <!-- resource-topic -->
        Original link, version, precise location and related learning topics or practices. Reference the original Related or Discovery record.
    - 💡 Concepts · s1N <!-- concepts -->
      Explain what and why; name topics after concrete learning questions.
      - s1N-〈concept-question〉 <!-- concept-topic -->
        Meaning, mechanism, example and counterexample.
    - 🧭 Methods · s2N <!-- methods -->
      Explain how, why that method works, and its conditions.
      - s2N-〈method-question〉 <!-- method-topic -->
        Derivation or procedure, linked to relevant practice results.
    - 🔗 Connections and Applications · s3N <!-- connections -->
      Connect knowledge to other concepts, practical choices and limits.
      - s3N-〈application-question〉 <!-- connection-topic -->
        Several topics can support one practice Job and cite the same sources.
    - 🤔 Questions · s4N <!-- questions -->
      Keep the questions that come up while learning; each gets its own topic.
      - s4N-〈learner-question〉 <!-- question-topic -->
        The question as asked, its answer, and the concept or method topic it leads back to.
