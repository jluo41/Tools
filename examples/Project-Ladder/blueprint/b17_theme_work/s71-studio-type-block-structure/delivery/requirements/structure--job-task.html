Structure ›Job-Task

What
How a Block of this type divides its work: Job group, Job, Task group, Task.
Why
Two Blocks of one type then divide their work the same way, so a reader finds a Task where it is expected.
Must show
  1. at most four levels: Job group → Job → Task group → Task
  2. only the levels the type needs; a level it never uses is left out, not shown empty
  3. "optional" only where real Blocks of the type differ
  4. drawn as a folder tree like Folder, each level its own colour, the same colour in every Block type
  5. the four lists pinned in the topic's types.md: 〈Job group type 1〉, 〈2〉 …; 〈Job type 1〉, 〈2〉 …; 〈Task group type 1〉, 〈2〉 …; 〈Task type 1〉, 〈2〉 …
  6. each type with its name, what it is for, and what a Job or Task of that type must hold
  7. a type is fixed for the Block type; a group is named by each Block or Job on its bands: line, and is one of the group types
  8. a Task's Runs on its hover only when a Run means something structural
Pattern
  • ◇〈Work Block (type)〉
    • ◇〈job-group-name〉Job group
      • ◇jNN_〈job〉Job name
        • ◇〈task-group-name〉Task group
          • ◇tNN_〈task〉Task name
From
the type's levels and their allowed types
Check
block_types_check.py: every Job type and Task type of the example Block is one types.md lists; by eye: the levels match the type
