# Idea Block structure · open choices

The shared top views are **Structure / Draw / Examples / Skills**. Structure keeps
Jobs/Tasks and Studio as left entries. Draw contains the named Idea hierarchy.

## Which real Idea Block should bind Examples?

- **The contract's robustness direction:** Calibration under shift and Missingness robustness provide meaningful candidate names for this illustrative design.
- **A verified working Idea Block:** its actual candidate questions and authored assessments become the example once bound.

Leaning: keep the contract-based design clearly marked as illustrative in the
face; show Examples entries only when bound to verified Blocks, using their
actual titles and routes. The current diagram does not assert live records.

## Which groups help compare candidates and their assessments?

- **Ideas:** the default Job grouping until actual sub-directions justify others.
- **Framing / Assessment / Decision:** proposed Task lenses with named outputs such as Falsifiable claim, Closest-work comparison and Development recommendation.
- **Research design:** a proposed Studio group for Direction map and Assessment plan.

These groups describe useful content, not a required sequence or extra folders.
The open choice is whether the first real Block's questions need different names.

## How should the shared Job type be stored?

Idea Job is already recognized by `kind: ideation-unit`, `layout: idea-job` and
ownership checks. A separate `job-type` field is not defined by the current
shared Job contract. Keep that binding until a shared type-field decision is made.
Task Type remains `ideation`; candidate and deliverable names are instances,
while Ideas / Framing / Assessment / Decision remain navigation groups.

## How should examples link into Skills?

- **Link from each Task's methods:** puts the relevant contract beside the work.
- **Link from the example's skill list:** groups its methods in one place.

Leaning: link from each Task's methods. The Skills top view remains the complete
reference, with skill names on the left and their functions and checks together
on the right. No additional Studio is needed for a skill.

## How should an Idea link to a Grant?

- **Shared source identity, separate target adapters:** one scientific origin; each target validates its own requirements.
- **Universal destination packet:** less repeated machinery, but risks treating planned research as established evidence.

Leaning: share revision and decision rules while target requirements remain with their adapter. The current implementation validates the Paper route only.
