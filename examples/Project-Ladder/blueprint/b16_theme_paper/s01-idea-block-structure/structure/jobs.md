# Idea Job and Task organization

Read [the type catalog](../types.md), [the organization tree](jobs.html#jobs-rules), and [the Studio rules](studio.md).

The hierarchy is Job group → Job → Task group → Task. Types define content and behavior; groups organize selection; names identify instances. Use only levels the contract needs. Type details remain in types.md.

The trees describe the proposed organization, not invented live records. Research folders and execution adapters retain their present contracts until a separate implementation and migration is verified.

Structure follows the shared Block Structure Studio Type: Folder, Job-Task and Studio are folder-style trees. Job group, Job name, Task group and Task name use the common level colours; each row explains its purpose on hover. Names and parentage come from the authored outlines.
