# Idea Studio organization

These are the design topics of an actual Idea Block. Each band groups design questions; its Studio type describes the content of an individual topic. Names in 〈 〉 are proposed. Create only topics needed by the work; omit empty bands. Existing topics keep their identifiers.

| Band | Name | Studio type | One topic addresses |
| --- | --- | --- | --- |
| s0N | 🗺️ 〈Landscape〉 | 〈Idea Map〉 | Map the problem families and candidate Jobs within the direction. |
| s1N | 🔗 〈Connections〉 | 〈Idea Relations〉 | Compare shared assumptions, alternatives, dependencies and lineage across candidate Jobs. |
| s2N | ⚖️ 〈Comparison〉 | 〈Idea Comparison〉 | Compare candidates against explicit evidence and selection criteria. |
| s3N | 🌱 〈Development〉 | 〈Research Plan〉 | Explore how selected Ideas can form a Paper or Grant; decisions remain with the source Jobs. |

A topic concerning only one Job belongs beside that Job’s Tasks. Block-level topics compare candidates or define shared choices. Studio references work records; it does not duplicate their evidence, approvals or selection receipts.

The shared hai-studio contract owns topic folders and numbering. The Blueprint’s own Block Structure / Preview / Skills bands do not become the bands of this research Block.
