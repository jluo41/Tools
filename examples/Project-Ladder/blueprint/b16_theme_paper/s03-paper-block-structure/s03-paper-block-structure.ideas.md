# Paper Block Structure · open choices

## Which type contracts need to be defined?

The Job groups are settled: Story, Evidence, Display, Writing and Presentation. Their names do not automatically register Job types. The reader currently identifies Writing Version and legacy Display/Value/Citation/Submission branches. The proposed Story and consolidated Evidence Jobs need contracts; Presentation needs a deliberate format/workflow decision.

At Task level, draft is an established prose contract. Paper value faces use value, which is absent from the shared registry. Citation faces use evidence, which the base owner defines as numeric extraction. Final Paper figures/tables are not upstream display-input Tasks. Portal packaging is not a stored-table description. Resolve these contracts before scaffolding or migrating work.

## How should names and types be stored?

- Explicit semantic fields keep type, name and group independent.
- Existing readers infer some types from folder names; preserve those addresses during compatibility work.
- Leaning: explicit fields with documented compatibility, never infer new group membership from jNN/tNN decades.
- Open: the precise shared field names and migration procedure.
