### Key Points
- **Board 对齐**：之前 open task 与已有 task 大部分已对应；少量 result 因未迁移没对上，但 evaluation 侧 OK。
- **未实现项处理**：AI 遇到"需 aggregate/summary 但无 receipt"时，不特殊 mark，只写 `NO_RECEIPT` / `not implemented`，由 project skill 扫描代码定位，比让 AI 扫更高效。
- **Fine-tune 进度**：昨天跑了 100M 模型 4 epochs 约十几分钟；今天在跑多个 seed 求平均。AI 建议 tune 整个 backbone，但决定沿用只 train last layer 的方案。一两周内可跑完。
- **GPU 利用**：100M 模型单卡可并行 2-3 个，可规划成新的 job 批跑。
- **AI-Ready 数据**：现有 V3，最新据悉是 V4（Marvis 11 月前拿不到），暂不额外要数据，可考虑在现有数据上做 demographic prediction 建立 downstream logic。
- **Workbench 结构**：Space → Section → Block → Job → Task → Run，当前最大痛点是久未看的 block 难以快速 pick up。
- **Studio 定位**：作为"中央红头文件"指导下层，只在 block level 出现，避免 navigation 过深（点击总数 ≤ 6）。可用 excalidraw 自动生成/修改逻辑图，比 Si-draw 自己拽框快很多。
- **Delivery 定位**：应保留在最 high level，因为交付内容常跨多个 block（会议/paper/presentation 用）。
- **Report 分层**：block/job/task 都应有 report，但各层级 report 什么问题尚未想清楚，倾向于"做中积累、写 skill 总结"。
